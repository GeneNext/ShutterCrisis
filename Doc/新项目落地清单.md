# 新项目落地清单

本文是**从基座复制出新工程后，第一次把它变成“自己的项目”**的可勾选清单。按顺序执行，每项都给出“改哪个文件 / 命令”和“怎么验证改对了”。

> 适用范围：从基座仓库（`GamePrototype` / 本仓 `ShutterCrisis`）复制出一份新工程后使用。  
> 基本原则：先改名与资源地址，再改服务器身份，再建首批面板，最后接门禁与合规检查。  
> 当前基座仍在并行迁移；`⚠ 待验证` 项表示必须先补齐/确认对应文件存在再执行。

## 关于本文里的名字（**改名后必读**）

本清单原先由基座 `GamePrototype` 编写，文中的“目标名”示例都是 `GamePrototype`。  
本仓 `ShutterCrisis` 已经用 `python Tools/rename_project.py --to ShutterCrisis` 做过一次完整改名，因此：

- **本仓自身就是 `ShutterCrisis`**，不要再对本仓执行“改名成 ShutterCrisis”这一步；那是给**下一层新项目**用的。
- 文中所有 `GamePrototype*` / `gameprototype` 示例都应读作“**你新项目的名字**”（如 `YourGame.Framework` / `yourgame.service`）。
- 文中少数运行结果 / 实测计数（例如“含该名字的文件数”）是写清单当时的快照，与本仓现状不一定一致；不要把它当断言，以实际 `grep` 为准。

- ⚠ `Server/README.md` 声称 `GP_PRUNE_INTERVAL` 会回退旧名 `CK_PRUNE_INTERVAL`；当前 `server.py` 通过 `EnvValue` 读取，而 `LEGACY_ENV_FALLBACK` 只登记了 `GP_STORAGE` / `GP_DATABASE_URL`。这是一处“文档与代码不一致”，使用 `CK_PRUNE_INTERVAL` 前需先修代码或不要依赖它。

### 4.3 域名与 HTTPS

- 服务器：`--https-cert` / `--https-key` 启动 HTTPS，或前置 Nginx 反代。
- 客户端：`GameConst.ServerUrl` 改成 `https://api.<你的域名>/api`。
- 资源 CDN：`AssetCdnConfig.CdnRoot` 改成 `https://cdn.<你的域名>/bundles`。
- 平台后台：把 API 域名与 CDN 域名加入微信 / 抖音 / TapTap 等渠道的 request / downloadFile 合法域名白名单。
- 小游戏会拦截明文 HTTP 与裸 IP；上线前必须使用已备案 HTTPS 域名。

## 五、建你自己的首批面板

1. 决定首批窗口 / 面板清单（建议先做登录、主页面、2–3 个核心功能窗）。
2. 在面板注册源登记：`PanelMVC.xml`（当前 `XmlWindowDataProvider` 读取）与 / 或 `PanelDataSO.asset`（目标持久化源）——**只选一个写入源**。
3. 在 `PanelNavRule.BuildRules()` 登记层、互斥组、是否进返回栈。
4. 运行“一键生成”得到标准窗口骨架；需要真实内容的面板可手工调整 Prefab，但必须保留 `TitleText` / `ContentRoot` / `StatusText` / `ActionButtons` 四个字段绑定，之后只用“补建缺失”。
5. 执行“一键生成”：
   - 菜单 `ShutterCrisis/一键初始化工程`（目标命名；当前代码仍使用旧项目名 / 旧菜单根）；
   - 或面板生成器窗口的“一键生成（全量重置）”。
6. 检查：
   - 生成前自检 `KitchenPanelPrefabGenerator.ValidateAll()` 无问题；
   - `Assets/Prefabs/UI/Panels/` 下 Prefab 生成；
   - 面板能进 / 能关 / 能返回；
   - 改过中文文案时字体子集已刷新。

当前 `KitchenPanelPrefabGenerator` 是通用生成器，按面板配置产出标准窗口骨架（绑定 `TitleText` / `ContentRoot` / `StatusText` / `ActionButtons`）；`KitchenPlaceholderPrefabGenerator` 只补缺失，交给通用生成器产出骨架；`GameContentResetTool` 是 9 步流水线，主场景第 1 步只检查不重建。

**本仓已实测关掉的旧缺口**（`verify_action_contract.py` 的双向校验现在按**类名精确取体**，
只比对 `class KitchenActionType`；`verify_client_static.py` 的 meta / 枚举检查也已通过）。
详见 [`验证与门禁.md`](验证与门禁.md) 第九节的实测表。

## 六、建立门禁脚本并接入 CI

### 6.1 本地全量门禁顺序

```bash
# 客户端
python Tools/compile_check/compile_check.py --errors-only
python Tools/unity_check/unity_check.py --errors-only
python Tools/font_subset/make_ui_font.py --check
python Tools/text_table/make_text_table.py --check

# 服务器
cd Server
python -m compileall -q .
python -m gameplay.verify
python test_client.py http://127.0.0.1:8611
python e2e_test.py    http://127.0.0.1:8611
python test_heartbeat.py
python verify_plugin_arch.py --client ../Client
python verify_action_contract.py --client ../Client
python verify_client_static.py --client ../Client
python verify_asset_manifest.py --dir <产物目录> --server <地址> --platform <渠道>
python verify_deploy.py
```

`verify_client_static.py` / `verify_plugin_arch.py` / `verify_action_contract.py` 不显式传客户端目录时，客户端侧规则可能不执行或按默认布局探测；CI 里必须显式传参。
**本仓实测（2026-09-13）**：`verify_plugin_arch.py --client ../Client` PASS 8 / FAIL 0（11 实现 == 11 目录）；
`verify_action_contract.py --client ../Client` PASS 6 / FAIL 0（17 个 ActionType 一致）；
`verify_client_static.py --client ../Client` PASS 6 / FAIL 0（205 个脚本）。

### 6.2 CI 示例（按你的 CI 平台调整）

```yaml
# 伪代码：每一步都必须以非 0 退出码失败
steps:
  - name: client-stub-compile
    run: python Tools/compile_check/compile_check.py --errors-only
  - name: client-static
    run: cd Server && python verify_client_static.py --client ../Client
  - name: plugin-arch
    run: cd Server && python verify_plugin_arch.py --client ../Client
  - name: action-contract
    run: cd Server && python verify_action_contract.py --client ../Client --action-type-file <只含协议 ActionType 的文件>
  - name: server-tests
    run: |
      cd Server
      python -m compileall -q .
      python -m gameplay.verify
      python test_heartbeat.py
  - name: font-subset
    run: python Tools/font_subset/make_ui_font.py --check
  - name: text-table
    run: python Tools/text_table/make_text_table.py --check
```

**验证**：故意在客户端引入一条越层引用 / 一个裸事件名 / 一个未注册 ActionType，确认对应门禁变红；移除后复绿。门禁必须能用“违规探针”验证，不能只看它恒 PASS。
