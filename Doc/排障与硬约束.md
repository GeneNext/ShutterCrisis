# 排障与硬约束（ShutterCrisis：运行期 / 程序集 / 序列化）

> 本文件沉淀一类「编译能过、运行期才炸」的问题：**单例从未实例化、资源加载路径不匹配、
> 跨程序集引用 `UnityEditor`、序列化字段未接线**。`compile_check` 抓不到这类问题（本机真编译批处理还会在
> AssetDatabase 初始资源刷新处挂死），只能靠运行时栈 + 人工审阅定位。
> 规则部分同时进 `AGENTS.md` §3.10，作为「动手前必读」的防回潮红线。

---

## 一、本次修复记录（新内容）

### 1. 编译器告警（CS0105 / CS0108 / CS0114 / CS0618 / CS0414）

- **核心约定**：`BaseInstance_Mono` 的 `Instance` 是**非虚静态属性** → 子类必须加 `new`；
  `Awake`/`OnDestroy` 是 `protected virtual` → 子类必须加 `override`。漏标会出现 CS0108/CS0114 且行为可能异常。
- `CreatePanelRelatedScriptsEditor` 在 `GetPart_Top()` 已含 `using UnityEngine;` 后又加了一遍 →
  CS0105 重复 using；根因修在生成器，并脚本去重 13 个 `*View.cs`。
- `ScreenOrientation.Unknown` 过时 → 改 `AutoRotation`；`SimpleJoystick.m_lastFrameSpeed` 死字段 → 删除。

### 2. 运行期 NRE：单例从未实例化（AssetDownloader / RunCatalogLoader + 系统性）

- **现象**：`BaseInstance_Mono<X>.get_Instance` 报 `instance is missing` → `AssetHotUpdateService.EnsureReady` /
  `RunCatalogService.Load` 抛 `NullReferenceException`。
- **根因**：`X.m_instance` 由 `BaseInstance_Mono.Awake` 登记，但全工程无任何 `new GameObject + AddComponent`
  创建点（组合根 `KitchenClientBootstrap` 只建了 `AssetLoader`），于是 `m_instance` 恒为 null，访问即 NRE。
- **修复**：
  - `KitchenClientBootstrap.Awake` 在「① 资源热更」之前 `CreateNode<AssetDownloader>()` /
    `CreateNode<RunCatalogLoader>()`；
  - `AssetHotUpdateService.EnsureReady` / `RunCatalogService.Load` 加**空值守卫**（null 时走失败降级，不抛异常，
    契合「全程不抛异常」契约）；
  - `AssetLoader` / `AssetBundleManager` / `SceneLoader` / `LoginManager` / `PlayerDataStore` / `CoroutineHost`
    对齐 `AssetBundleManager` 的**自创建 `Instance`** 约定（直接给 `m_instance` 赋值，同步可用、不依赖 Awake 时序）。

### 3. 运行期错误：`PanelManager prefab not found`

- **现象**：`OpenFirstPanel` → `PanelManager.Instance` 从 `Resources/PanelManager` 加载 Prefab 失败 → 返回 null → 崩溃。
- **修复**（`PanelManager.Instance` getter）：Prefab 缺失时**不再返回 null**，改为运行时自举 ——
  `new GameObject("PanelManager") + AddComponent<PanelManager>()` + `prefabInstance.EnsureFallbackUI()`
  （复用 `PanelManagerFallback` 自建 EventSystem / Canvas / PanelCamera / 四层根）。
  正式 `Resources/PanelManager.prefab` 生成后自动切回 Prefab 路径。

### 4. 运行期错误：`PanelView load failed`（面板 Prefab 加载路径不匹配）

- **现象**：`LoadView` 用 `windowID` 当路径 → `Resources.Load("LoginWindow/LoginMainPanel")` 找不到。
- **根因**：`AssetLoader.m_assetLoadType` **硬编码为 `Resources`**（全工程无别处赋值），但面板 Prefab 由
  `KitchenPanelPrefabGenerator` 生成在 `Assets/Prefabs/UI/Panels/...`（**非** `Resources` 目录）。
  `PathConst.PANEL_PREFAB_PATH` 的注释明确写「编辑器用 AssetDatabase 加载」；
  `PANEL_RESOURCES_ROOT = "UI/Panels/"` 才是真机 Resources 路径。
- **修复**：
  - `AssetLoader` 新增 `LoadPanelPrefabInstance(windowID, assetName)`：默认 `Assembly-CSharp` 程序集内用
    `AssetDatabase.LoadAssetAtPath(PANEL_PREFAB_ROOT/窗口/面板.prefab)` 实例化；真机返回 null；
  - `PanelManager.LoadView` 编辑器分支改调该助手，真机分支走 `PANEL_RESOURCES_ROOT`（构建流程会把
    `Prefabs/UI/Panels` 拷贝/打包进 `Resources/UI/Panels`）。

### 5. 运行期异常：`UnassignedReferenceException`（面板序列化字段未接线）

- **现象**：`OpenPanel` 读 `panelView.RectTrans.anchorMin` 抛 `m_rectTrans has not been assigned`。
- **根因**：全部 13 个面板 Prefab 的 `m_rectTrans` / `m_canvas` / `m_panelEffectControl` 均为 `fileID: 0`
  （生成器产出时未给 View 组件接线）。`PanelView.Init()` 从不解析这些字段。
- **修复**（`PanelView.Init`）：**直接赋值** `m_rectTrans = GetComponent<RectTransform>()` 等三条（见规则 4）。
  派生 `*View.Init()` 都 `base.Init()`，故一次修复覆盖全部 13 个面板。

## 二、硬约束 / 规则（防回潮，亦见 AGENTS.md §3.10）

1. **`BaseInstance_Mono` 单例必须被实例化**：组合根或自创建 `Instance` getter 要保证 `m_instance` 非 null；
   访问前若可能为 null，先加空值守卫降级，绝不让它抛 NRE。
2. **资源加载路径与加载模式要对齐**：`AssetLoader.m_assetLoadType` 当前固定 `Resources`，
   面板 Prefab 编辑器期在 `Prefabs/UI/Panels`（AssetDatabase 源目录），真机在 `Resources/UI/Panels`。
   加载面板务必按环境用对路径/模式，**不要用裸 `windowID` 去 `Resources.Load`**。
3. **`ShutterCrisis.UI` 等自定义 asmdef 不能直接引用 `UnityEditor`**：编辑器资产加载逻辑必须下沉到
   默认 `Assembly-CSharp` 程序集（`AssetLoader` 所在），用 `#if UNITY_EDITOR` 包裹。
4. **序列化字段「未赋值」（fileID:0）必须直接赋值覆盖，不能先读再判空**：读未赋值字段本身就会抛
   `UnassignedReferenceException`；在 `Init`/`Awake` 里用 `GetComponent` 直接写即可清除未赋值态。
5. **`PanelManager` Prefab 缺失时走 `PanelManagerFallback` 兜底**，不要返回 null 让上层崩。
6. **面板 Prefab 由生成器产出但序列化引用常未接线**：View 的引用类字段优先在 `Init` 运行时自解析，
   不依赖 Prefab 逐字段手动接线。

## 三、验证纪律

- 本机 `compile_check`（真编译批处理）会在 AssetDatabase Initial Refresh 处**挂死**（环境坑，非代码问题），
  **无法在此机复跑编译**；改动靠人工审阅 + 文本/文件校验（`grep` `fileID:0`、比对 Prefab 组件 GUID 与 `.cs.meta`）
  + Unity 时序分析确认。
- 真机/编辑器门禁以 `Doc/验证与门禁.md` 为准；面板相关改动建议在 Hub 实跑整条启动链
  （热更 → 拉目录 → 建引擎 → 登录 → 同步 → 切场景 → 开首屏）确认 **0 告警、0 NRE、0 运行期 error**。
- 正式 `Resources/PanelManager.prefab` 与面板 Prefab 的逐字段接线，仍需在 Hub 重跑
  「`ShutterCrisis/一键初始化工程`」生成（届时 `PanelManager.Instance` 与 `LoadView` 会自动切回 Prefab 路径）。
