# 服务器基座

本文描述 `ShutterCrisis` 服务器基座的技术栈、分层、完整 API 协议、登录语义、心跳与会话留痕、`GP_*` 环境变量、双存储后端、玩法插件接入、本地用例与部署回滚。

> 适用范围：`E:\Projects\Game\ShutterCrisis\Server`。  
> 目标：零第三方运行时依赖，Python 3 标准库即可起服；玩法细节全部在 `gameplay/plugins/` 里，服务器框架本身不含任何具体玩法规则。

## 一、技术栈与拓扑

| 项 | 值 |
| :--- | :--- |
| 语言 / 运行时 | Python 3（标准库） |
| HTTP 服务器 | `http.server.ThreadingHTTPServer` + `BaseHTTPRequestHandler` |
| 默认端口 | `8611`（`server.py::DEFAULT_PORT`） |
| 默认数据目录 | `Server/data`；本地联调常用 `Server/.testdata` |
| HTTPS | 启动参数 `--https-cert` / `--https-key`（或环境变量 `HTTPS_CERT` / `HTTPS_KEY`） |
| 路由层 | `Server/server.py` |
| 服务层 | `Server/services/` |
| 玩法层 | `Server/gameplay/` |
| 存储 | JSON（默认）或 PostgreSQL（`GP_STORAGE=postgres`） |
| 部署 | systemd：`Server/shuttercrisis.service`；首次安装：`Server/install_service.sh`；增量部署：`Server/deploy.py` |

拓扑：

```text
客户端
  │ HTTP (JSON)
  ▼
Server/server.py
  ├─ do_GET / _route_post
  ├─ 参数挑选
  └─ services/*
        ├─ account.py      账号 / 登录 / 存档 / 限流 / 封禁
        ├─ session.py      心跳 / 在线留痕
        ├─ run.py          单局生命周期（start / state / action / settle）
        ├─ catalog.py      目录聚合
        ├─ asset.py        资源清单 / bundle 托管分发
        ├─ admin.py        后台管理
        ├─ storage.py      存储后端抽象
        └─ postgres_storage.py  PostgreSQL 实现
              │
              ▼
        gameplay/*
          ├─ core.py        单局节奏常量 / 目录注册表
          ├─ state.py       状态容器 / 资源工具 / 清洗钩子
          ├─ actions.py     行动注册表 / 前置条件 / 分发
          ├─ events.py      随机事件框架
          ├─ rounds.py      回合推进 / 离线补算
          ├─ settle.py      结局 / 结算 / 奖励
          ├─ plugins/       玩法插件（自动发现）
          └─ verify/        自检框架
```

## 二、三层职责

### 2.1 路由层：`Server/server.py`

只做四件事：

1. HTTP 收发：CORS、JSON 解析、请求体大小限制（`MAX_BODY_BYTES = 4MB`）、统一错误响应。
2. 路由分发：`GET /health`、`GET /api/catalog`、`GET /api/asset/*`、`POST /api/*`、`POST /api/admin/*`。
3. 参数解析：从请求体挑出服务需要的 `token` / `code` / `platform` / `action` / `options` 等。
4. 启动：读启动参数、`BuildStore()`、注入 `RUN_SERVICE`、启动清理线程、拉起 HTTPServer。

**禁止**：在 `server.py` 里写具体玩法判定；具体业务放 `services/*`。

### 2.2 服务层：`Server/services/`

| 文件 | 职责 |
| :--- | :--- |
| `account.py` | `Store`（账号 / token / 封禁 / 昵称）；登录三通道；存档 `Sync` / `Save`；`ServerVersion` 单调递增；登录 / 写接口限流；平台 OAuth |
| `session.py` | `Heartbeat` / `OnlineSnapshot` / `ThrottleHeartbeat`；在线留痕，与玩家存档物理隔离 |
| `run.py` | `RunService`：开新局、状态查询（含离线推进）、行动、结算；跨局收益回写钩子、开局播种钩子 |
| `catalog.py` | 把 `gameplay` 注册的目录 / 行动 / 结局 / 事件 / 单局节奏聚合为 `GET /api/catalog` |
| `asset.py` | 资源清单读写、bundle 托管分发、增量备份 |
| `admin.py` | `/api/admin/*` 后台业务函数 |
| `storage.py` | `StorageBackend` 协议、`JsonStorageBackend`、`CreateBackend`、留存默认值 |
| `postgres_storage.py` | `PostgresStorageBackend`、`DDL_STATEMENTS`、快照 + 版本模型 |
| `health.py` | `GET /health` 响应体，O(1) 探活 |

### 2.3 玩法层：`Server/gameplay/`

| 文件 | 职责 |
| :--- | :--- |
| `core.py` | 单局节奏常量（`GP_MATCH_HOURS` / `GP_TOTAL_ROUNDS` 可覆盖）；目录注册表 `RegisterDirectory`；文案 ID `NameIdOf` |
| `state.py` | `NewState` / `SanitizeState`；资源与设施通用读写工具；清洗 / 初始化钩子 |
| `actions.py` | `ACTION_REGISTRY`、`RegisterAction`、`RegisterPrecondition`、`ExecuteAction` |
| `events.py` | `RegisterEvent`、`TriggerRandomEvent`、`GP_EVENT_CHANCE` |
| `rounds.py` | `RegisterRoundHook`、`RegisterEndCondition`、`ResolveRound`、`AdvanceOffline` |
| `settle.py` | `RegisterEnding`、`RegisterSettleHook`、`RegisterRewardHook`、`RegisterEndingRule`、`SettleRun` |
| `plugins/` | 自动发现；`ACTIONS` / `Register()` / `VERIFY` 约定 |
| `verify/` | 聚合插件自检；`python -m gameplay.verify` |

## 三、完整 API 协议表

### 3.1 通用约定

- 请求体默认 `application/json`。
- 业务失败通常返回 HTTP 200 + `{"Success": false, "Message": "..."}`；路由不存在返回 HTTP 404；后台未授权返回 HTTP 403；未捕获异常返回 HTTP 500。
- 响应 JSON 字段名区分大小写，客户端 DTO 必须与此一致。
- 协议字段名是兼容红线：`Token` / `PlayerId` / `ServerVersion` / `PlayerDataJson` / `code` / `deviceCode` / `platform` / `clientVersion` / `deviceModel` / `os`。

### 3.2 健康检查

| 方法 | 路径 | 请求 | 成功响应 |
| :--- | :--- | :--- | :--- |
| `GET` | `/health` | 无 | `{"status":"ok","serverVersion":"1.0","serverTime":<unix秒>}` |

`services/health.py::Health(version)` 只返回进程存活与服务器时间；不查库、不鉴权、不写盘。

### 3.3 登录与账号

#### `POST /api/login`

请求体支持三种通道：

| 通道 | 字段 | 说明 |
| :--- | :--- | :--- |
| 凭证登录 | `code`, `platform`, `deviceCode` | 注册 / 登录合一；平台 OAuth 配置可用时走 `code2session` 换稳定 openid |
| Token 登录 | `token`, `platform` | 校验并换发新 token；旧 token 立即失效 |
| 账号密码 | `username`, `password`, `platform` | 编辑器 / PC 端；服务端存 pbkdf2 摘要 |

公共可选字段：`clientVersion` / `deviceModel` / `os`，登录成功后由 `Store.RecordClientInfo` 写入账号表的 `lastClient`，不碰玩家存档。

成功响应字段：

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `Success` | bool | 是否成功 |
| `Token` | string | 新 token（90 天有效期） |
| `PlayerId` | string | 玩家 ID，形如 `p_<hex>` |
| `Message` | string | 人类可读消息 |
| `PlayerDataJson` | string | 云端存档原文；新玩家为空串 |
| `HasNickname` | bool | 是否已设置过昵称 |
| `ServerTimestamp` | int | 服务器 unix 秒 |

失败响应同样包含上述结构，`Success=false`、`Token=""`、`PlayerId=""`。常见失败：缺少凭证、Token 无效或过期、平台 code 校验失败、账号被封禁。

#### `POST /api/register`

请求：`username` / `password` / `platform`。  
响应：与 `/api/login` 账号密码通道一致；注册即登录，返回新 token。  
账号规则：`^[A-Za-z0-9_]{4,24}$`；密码 6–32 位。

#### `POST /api/setnickname`

请求：`token` / `nickname`。  
响应：`{"Success":bool,"Message":string,"ServerTimestamp":int}`。  
昵称规则：`^[\u4e00-\u9fa5A-Za-z0-9_]{2,12}$`；全局唯一，大小写不敏感；同一玩家已设置过昵称后暂不支持修改。

### 3.4 存档

#### `POST /api/sync`

请求：`token`。  
响应：`{"Success":bool,"Message":string,"PlayerDataJson":string,"ServerTimestamp":int}`。

#### `POST /api/save`

请求：

| 字段 | 必填 | 说明 |
| :--- | :--- | :--- |
| `token` | 是 | 登录令牌 |
| `jsonData` | 是 | 存档 JSON 字符串；也兼容 `playerDataJson` / `playerData` / `data` |
| `platform` | 否 | 渠道标识 |

响应：`{"Success":bool,"Message":string,"ServerVersion":int,"ServerTimestamp":int}`。

服务端行为（`Store.SavePlayer`）：

1. 解析 `jsonData`，必须是 JSON 对象。
2. 跑 `_ValidateSaveFields`（新项目可用 `RegisterSaveFieldRule` 登记字段范围）。
3. 同一玩家两次保存最小间隔 `SAVE_INTERVAL_MIN_SECONDS = 1` 秒，防误刷。
4. 读取当前存档的 `ServerVersion`，新版本 = 旧版本 + 1（单调递增）。
5. `LastSaveTimestamp` 防旧档覆盖：客户端时间戳早于服务器已存数据超过 `CLOCK_TOLERANCE = 300` 秒时拒绝。
6. 写入 `ServerVersion` / `ServerTimestamp` / `LastSaveTimestamp`，落盘。

客户端拿到 `ServerVersion` 后应回写本地 `PlayerData.ServerVersion`；多端同步时以服务器版本高者为准。

### 3.5 单局生命周期

#### `POST /api/run/start`

请求：

| 字段 | 必填 | 说明 |
| :--- | :--- | :--- |
| `token` | 是 | 登录令牌 |
| `options` | 否 | 玩法参数对象，原样传给 `gameplay.NewState(Options=...)` |
| `force` | 否 | `true` 时允许覆盖进行中的单局 |

同时兼容把 `region_id` / `meta_level` / `mode` / `difficulty` / `seed` 直接放顶层，由 `_RunOptions` 透传进 `options`。

响应：`{"Success":bool,"Message":string,"State":object|null,"HasActiveRun":bool,"Replaced":bool}`。

- 已有未结束单局且 `force=false`：`Success=false`，`State` 回带现有单局，`HasActiveRun=true`，客户端应提示“继续本局 / 结算并重开”。
- `force=true`：覆盖开新局，`Replaced=true`。

#### `POST /api/run/state`

请求：`token`。  
响应：`{"Success":bool,"Message":string,"State":object}`。  
`RunService.State` 会先 `LoadAndAdvance`：按真实经过时间补算回合（离线推进），再落盘。

#### `POST /api/run/action`

请求：`{"token":"...","action":{"ActionType":"...", ...}}`。  
响应：`{"Success":bool,"Message":string,"ActionResult":[...],"State":object}`。  
`RunService.Action` 持锁执行“读档 → 离线推进 → `gameplay.ExecuteAction` → 无论成败都落盘”，避免同一段离线时间被重复结算。

#### `POST /api/run/settle`

请求：`{"token":"...","force":bool}`。  
响应：`{"Success":bool,"Message":string,"State":object}`。  
未自然结束时只有 `force=true` 才允许提前结算；结算后跑 `RegisterRewardApplier` 回写跨局收益。

### 3.6 心跳与会话留痕

#### `POST /api/heartbeat`

请求（都可选，缺省为空串）：

| 字段 | 说明 |
| :--- | :--- |
| `token` | 登录令牌 |
| `platform` | 渠道标识 |
| `scene` | 当前场景 |
| `panel` | 当前面板，建议 `窗口_面板` |
| `action` | 最后动作 / `panel.open` / `panel.close` |
| `clientVersion` / `deviceModel` / `os` | 客户端信息 |

成功响应：

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `Success` | bool | 请求是否被处理 |
| `Message` | string | `ok` 或 `throttled` |
| `SessionOk` | bool | 会话是否有效；false 时客户端应停跳并回登录流程 |
| `Throttled` | bool | 仅限流命中时出现；本次未落盘但不代表断线 |
| `PlayerId` | string | 服务器认定的玩家 ID |
| `ServerTime` | int | 服务器 unix 秒 |
| `HeartbeatTtl` | int | 在线有效期，默认 300 秒 |

失败响应：缺少 token / token 无效时 `{"Success":false,"Message":"...","SessionOk":false,"ServerTime":...}`。

### 3.7 目录

#### `GET /api/catalog`

请求：无（可带 `?platform=`，当前实现不区分）。  
响应：`{"Success":true,"Version":"<内容 sha1 前 12 位>","Catalog":{...}}`。

`Catalog` 至少包含：

- 所有 `gameplay.core.RegisterDirectory` 注册的域（域名为键，值为条目数组）。
- `actions`：已注册 ActionType 的 `[{"id":..., "nameId":...}]`。
- `endings`：已注册结局。
- `events`：已注册随机事件。
- `matchConfig`：`{MatchHours, TotalRounds, RoundSeconds, TotalSeconds}`。

目录内容来自注册表，新增插件后自动聚合；`Version` 不变时客户端可跳过刷新。

### 3.8 资源热更与托管

#### `GET /api/asset/manifest?platform=<渠道>`

支持渠道（`services/asset.py::SUPPORTED_PLATFORMS`）：

`wechat` / `douyin` / `taptap` / `webgl` / `android` / `ios` / `standalone`。

成功响应：

```json
{
  "Success": true,
  "Manifest": {
    "version": "20260101120000",
    "platform": "webgl",
    "baseUrl": "https://cdn.example.com/bundles/webgl/20260101120000/",
    "files": [{"name": "prefabs/ui/panels/example.bundle", "md5": "32位hex", "size": 12345}],
    "publishedAt": 1767225600
  }
}
```

失败响应：`{"Success":false,"Message":"...","Platform":"...","Platforms":[...]}`。未发布时客户端应回退直读 CDN 的 `version.json`。

#### `GET /api/asset/file/<平台>/<bundle 相对名>`

无 CDN 时由服务器托管分发 bundle 本体。成功返回二进制流 + `Cache-Control: public, max-age=3600`；失败返回 404 JSON。

### 3.9 后台管理

后台接口统一在请求头带 `X-Admin-Key`，与服务器环境变量 `GP_ADMIN_KEY` 一致；未配置 `GP_ADMIN_KEY` 时后台接口整体 403。

| 方法 | 路径 | 请求 | 响应 |
| :--- | :--- | :--- | :--- |
| `POST` | `/api/admin/stats` | `{}` | `{Success,Stats}`：运行统计 + 账号/token/封禁规模 + 在线快照 |
| `POST` | `/api/admin/ban` | `{player_id, reason?}` | `{Success,Message}` |
| `POST` | `/api/admin/unban` | `{player_id}` | `{Success,Message}` |
| `POST` | `/api/admin/account` | `{player_id}` 或 `{code}` | `{Success,Account}` |
| `POST` | `/api/admin/save` | `{player_id, full?}` | `{Success,Save}` 或 `{Success,SaveJson}` |
| `POST` | `/api/admin/reset` | `{player_id, confirm:"RESET"}` | `{Success,Message}`；原档备份为 `.bak.<时间戳>` |
| `POST` | `/api/admin/asset/manifest` | `{platform, manifest}` | 与 `AssetManifestSet` 相同 |
| `POST` | `/api/admin/asset/backup` | `{}` | `AssetBackupStats` |
| `POST` | `/api/admin/retention` | `{}` | `{Success,Retention}` |
| `POST` | `/api/admin/retention/set` | `{kind, keep_days}` | `{Success,Message,Retention}` |
| `POST` | `/api/admin/asset/file?platform=&name=` | 原始二进制 body | `{Success,Message,Platform,Name,Size,Md5}` |

**安全提示**：后台接口默认是明文 HTTP。线上务必经 SSH 隧道或 HTTPS 调用，不要把 `GP_ADMIN_KEY` 暴露在公网请求中。

## 四、登录语义

### 4.1 三种通道

| 通道 | 账号键 | 用途 |
| :--- | :--- | :--- |
| `code` | 平台 OAuth 配置可用时 `"<platform>:<openid>"`；否则有 `deviceCode` 时 `"device:<deviceCode>"`；否则 `code` 原样 | 小游戏 / 游客登录 |
| `token` | 原账号 | 二次登录，校验并换发新 token |
| `username` + `password` | `"editor:<小写用户名>"` | 编辑器 / PC 端 |

### 4.2 `code` 与 `deviceCode`

`services/account.py::_ResolveAccountCode` 的优先级：

1. `WECHAT_APPID` / `WECHAT_SECRET`、`DOUYIN_APPID` / `DOUYIN_SECRET` 已配置时，调用平台 `code2session` 换 openid，账号键为 `渠道:openid`。
2. 未配置平台 OAuth 但带 `deviceCode` 时，账号键为 `device:<deviceCode>`，保证一次性 code 不会每次登录都产生新账号。
3. 最后回退 `code` 原样，用于测试 / 原型模式。

### 4.3 Token 与版本

- `TOKEN_TTL_SECONDS = 90 * 24 * 3600`。
- `LoginByToken` 走 `Store.RenewTokenIfValid`：单锁内校验并换发，旧 token 立即失效，防并发重放铸多 token。
- `SavePlayer` 每次成功保存都让 `ServerVersion` 单调递增；客户端用 `PlayerData.ServerVersion` 比较决定是否覆盖本地。
- `LastSaveTimestamp` 差值超过 `CLOCK_TOLERANCE = 300` 秒的旧快照会被拒绝，避免旧设备覆盖新存档。

### 4.4 限流与封禁

| 项 | 值 | 文件 |
| :--- | :--- | :--- |
| 登录窗口 / 上限 | 60 秒 / 60 次每 IP | `account.py` |
| 写接口窗口 / 上限 | 60 秒 / 120 次每 IP | `account.py` |
| 心跳窗口 / 上限 | 60 秒 / 300 次每 IP | `session.py` |
| 封禁 | 登录与全部鉴权接口拒绝，`ResolveToken` 视为无效 | `account.py` |

## 五、心跳与会话留痕

### 5.1 客户端触发

- 定时：登录后每 `GameConst.HeartbeatIntervalSeconds = 30f` 秒一次。
- 即时：操作、场景切换、面板打开 / 关闭各补一次。
- 去抖：`GameConst.HeartbeatDebounceSeconds = 1f`。
- 飞行中不叠加；飞行期间攒下的上下文在回包后补发一次。
- 失败不打扰玩家；`SessionOk=false` 时停跳并广播会话失效事件。
- 面板开关只有 UI 层知道，由 `SessionReporter.ReportPanel` 补上报。

### 5.2 服务端处理

`Server/services/session.py::Heartbeat`：

1. 规范化渠道 `NormalizePlatform`。
2. 校验 token：无 token / 无效 token 返回 `SessionOk=false`。
3. 限流命中返回 `Success=true + Throttled=true`，避免客户端误判断线。
4. 组装 `record`：`playerId` / `platform` / `scene` / `panel` / `action` / `clientVersion` / `deviceModel` / `os` / `ip` / `lastSeen` / `firstSeenAt` / `heartbeats`。
5. `store.RecordOnline(player_id, record)`：JSON 后端写 `data/online/<playerId>.json`，PG 后端写 `gp_online` 表。
6. 上下文变化时打一行 `[heartbeat]` 日志。

**红线**：心跳不改变任何游戏状态；在线留痕与玩家存档物理隔离；禁止把会话数据写进 `players/*.json`。

## 六、`GP_*` 环境变量清单

### 6.1 业务变量

| 变量 | 默认值 | 作用 |
| :--- | :--- | :--- |
| `GP_STORAGE` | `json` | 存储后端：`json` / `postgres`；旧名 `CK_STORAGE` 兼容 |
| `GP_DATABASE_URL` | 空 | PostgreSQL 连接串；旧名 `CK_DATABASE_URL` 兼容 |
| `GP_PRUNE_INTERVAL` | `3600` | 过期记录清理间隔（秒）；`<=0` 关闭 |
| `GP_ADMIN_KEY` | 空 | 后台接口密钥；未配置则 `/api/admin/*` 整体 403；兼容 `ADMIN_KEY` / `CK_ADMIN_KEY` |
| `GP_MATCH_HOURS` | `24` | 单局现实时长（小时） |
| `GP_TOTAL_ROUNDS` | `12` | 单局总回合数；`<=0` 时按 1 处理 |
| `GP_EVENT_CHANCE` | `0.25` | 回合末随机事件触发概率；`<=0` 关闭 |
| `ASSET_BACKUP_MAX_BYTES` | 2GB | 每平台 bundle 备份字节上限 |

### 6.2 启动与部署变量（非 `GP_` 前缀）

| 变量 | 默认值 | 作用 |
| :--- | :--- | :--- |
| `PORT` | `8611` | 服务监听端口（启动参数 `--port` 优先） |
| `DATA_DIR` | `Server/data` | 数据目录（启动参数 `--data-dir` 优先） |
| `HOST` | `0.0.0.0` | 监听地址（启动参数 `--host` 优先） |
| `HTTPS_CERT` / `HTTPS_KEY` | 空 | HTTPS 证书 / 私钥（启动参数同名优先） |
| `GP_DEPLOY_HOST` | 空 | `deploy.py` / `verify_deploy.py` 目标主机 |
| `GP_DEPLOY_USER` | `ubuntu` | SSH 用户 |
| `GP_DEPLOY_PORT` | `80` | 部署后验证端口 |
| `GP_DEPLOY_PEM` | 空 | SSH 私钥路径；未提供时读 `SSH_PASSWORD` |
| `GP_APP_DIR` / `GP_SERVICE` | `/home/ubuntu/shuttercrisis` / `shuttercrisis` | `install_service.sh` 部署目录 / 服务名 |
| `WECHAT_APPID` / `WECHAT_SECRET` | 空 | 微信平台 OAuth |
| `DOUYIN_APPID` / `DOUYIN_SECRET` | 空 | 抖音平台 OAuth |

## 七、存储双后端与留存策略

### 7.1 JSON 后端（默认）

数据目录结构：

```text
data/
├─ accounts.json      账号 code -> playerId
├─ tokens.json        token -> playerId（90 天）
├─ banned.json        封禁名单
├─ nicknames.json     昵称唯一索引
├─ retention.json     留存策略
├─ players/           <playerId>.json 玩家存档
├─ runs/              <playerId>.json 单局快照
├─ online/            <playerId>.json 在线留痕
└─ asset/             资源清单与 bundle 托管
```

写入策略：

- 先写 `.tmp` 再 `os.replace` 原子替换；
- 文件权限尽量 `chmod 600`；
- 损坏文件备份为 `.corrupt.<时间戳>`，不静默覆盖。

### 7.2 PostgreSQL 后端

配置：

```bash
export GP_STORAGE=postgres
export GP_DATABASE_URL='postgresql://user:pwd@127.0.0.1:5432/shuttercrisis'
python server.py --port 8611 --data-dir data
```

表结构（`services/postgres_storage.py::DDL_STATEMENTS`）：

| 表 | 作用 |
| :--- | :--- |
| `gp_players` | 玩家存档快照 + 版本 |
| `gp_runs` | 单局快照 + 版本 |
| `gp_online` | 在线留痕（覆盖式最新一条） |
| `gp_client_info` | 客户端信息 |
| `gp_retention` | 留存策略 |

模型：`id BIGSERIAL` + `player_id` 索引 + `version` + `payload JSONB` + `UNIQUE(player_id, version)`；读最新版本用 `ORDER BY version DESC LIMIT 1`。

驱动：`psycopg2` 惰性导入，未安装时只有切到 postgres 后端才报错，JSON 路径不受影响。

> ⚠ 待验证：`Server/services/postgres_storage.py` 文件自述“未在有 PostgreSQL 的机器上实测过 SQL 执行”；上线前务必在有 PG 的环境跑通 `migrate_json_to_pg.py --dry-run` 和真实读写。

### 7.3 迁移与回滚

```bash
cd Server
python migrate_json_to_pg.py --print-ddl   # 打印建表语句，人工核对
python migrate_json_to_pg.py --dry-run     # 预演：读取/比对全部 JSON，不写库
python migrate_json_to_pg.py               # 正式迁移；不删源文件
```

回滚：把 `GP_STORAGE` 改回 `json` 即可，源数据未动。

### 7.4 留存策略

默认值唯一定义在 `services/storage.DEFAULT_RETENTION_FALLBACK`：

| 类别 | 默认天数 | 说明 |
| :--- | :--- | :--- |
| `save` | `0` | 玩家存档永不自动删除（红线） |
| `run` | `90` | 单局记录 |
| `online` | `30` | 在线留痕 |
| `client` | `30` | 设备信息 |

后台可改：`POST /api/admin/retention/set`。清理线程按 `GP_PRUNE_INTERVAL` 定时跑 `store.PruneExpired()`，只清单局记录 / 在线留痕 / 设备信息。

## 八、如何加一个玩法插件

### 8.0 本作已有的玩法插件（先读它们，再动手写新的）

| 文件 | 域 | 一句话 |
| :--- | :--- | :--- |
| `plugins/_studio.py` | 共用状态契约（**不是插件**，`_` 开头会被跳过） | 状态键唯一定义处 + 现金/口碑/粉丝读写 + 固定/变动支出 + 跨域操作契约 |
| `plugins/studio.py` | 门店与现金流 | 目录（资源/设施/定价/品牌/扩张/经济调参）+ `SetPrice`/`UpgradeFacility`/`ExpandStudio`/`NextDay` + 每日现金流结算（`order=100`）+ 破产判定 |
| `plugins/orders.py` | 订单与拍摄 | 预约池生成与结清 + `TakeOrder`/`ShootOrder`/`DeliverOrder` + 拍摄微操评分 |
| `plugins/staff.py` | 员工与排班 | 招聘/培训/解雇 + 每天每人一次出错判定 + 士气与离职风险 |
| `plugins/market.py` | 广告 / 线上 / 品牌 / AI 冲击 | `RunAd`/`PublishContent`/`AdoptAI` + 粉丝自然增长 + AI 阶段推进 + 不可替代度净差 |
| `plugins/incidents.py` | 争执 / 锐评 / 客服 | `StartQuarrel`/`QuarrelMove`/`SubmitReview`/`ResolveServiceEvent` + 客服事件的**模态前置条件** |
| `plugins/random_events.py` | 环境随机事件 | 14 个跨系统事件（其余 4 个在各自域插件里） |

**写新插件前请先读 `Doc/玩法实现.md` 第二节**：里面讲了 `_studio` 为什么存在、
一天怎么走（回合钩子顺序）、**为什么现金流结算必须 `order=100`**、以及"确定性随机"的约束。

### 8.1 最小服务器插件

复制 `Server/gameplay/plugins/orders.py`（最完整的域）为 `Server/gameplay/plugins/my_domain.py`，
按需保留以下四类成员：

```python
# -*- coding: utf-8 -*-
"""my_domain.py —— 示例玩法插件（中性最小形态）"""

from .. import core
from .. import rounds
from .. import settle
from ..state import ResAdd, ResGet, ResSpend

PLUGIN_NAME = "示例域"

def HandleDoThing(St, Action, ReportLines):
    amount = int(Action.get("Amount", 1) or 1)
    if amount <= 0:
        return False, "Amount 必须为正数"
    ResAdd(St, "basic", amount)
    ReportLines.append("DoThing +%d" % amount)
    return True, "ok"

ACTIONS = {
    "DoThing": HandleDoThing,
}

def Register():
    # 可选：注册目录
    core.RegisterDirectory("resource", [
        {"id": "basic", "name": "基础资源", "desc": "示例资源"},
    ])
    # 可选：注册回合钩子
    rounds.RegisterRoundHook(OnRound, order=10)

def OnRound(St, lines):
    St["Score"] = int(St.get("Score", 0) or 0) + ResGet(St, "basic")

def VerifyMyDomain(gp, check):
    St = gp.NewState(RunId=1)
    ok, message = gp.ExecuteAction(St, {"ActionType": "DoThing", "Amount": 2}, [])
    check("DoThing 成功", ok, message)
    check("资源增加", gp.ResGet(St, "basic") >= 2)

VERIFY = [VerifyMyDomain]
```

**不需要改任何注册清单**：`Server/gameplay/plugins/__init__.py::DiscoverPlugins()` 会自动导入本文件，`RegisterAll()` 会自动收集 `ACTIONS` 与 `Register()`。

### 8.2 客户端对应

详见 [`分层与命令驱动.md`](分层与命令驱动.md) 的“新增一个玩法插件”：

- 客户端 `KitchenActionType` 必须有一个与服务器 `ACTIONS` 键完全同名的常量。
- 客户端 `KitchenUiAction` 提供面板入口键；面板只发入口键，由插件注册的行动构造器翻译成协议 Body。
- 若 `UiAction` 新增字段，必须同步 `KitchenCommandRunner` 的参数映射表。

### 8.3 玩法自检

在插件文件末尾声明：

```python
VERIFY = [VerifyMyDomain]
```

然后：

```bash
cd Server
python -m gameplay.verify
```

自检会聚合所有插件的 `VERIFY`；`verify_plugin_arch.py` 的 S6 也会跑一遍并要求 0 失败。

### 9.3 静态门禁

```bash
cd Server
python verify_plugin_arch.py --client ../Client
python verify_action_contract.py --client ../Client
python verify_client_static.py --client ../Client
python verify_asset_manifest.py --dir ../Client/AssetBundles/WebGL --server http://127.0.0.1:8611 --platform webgl
```

注意：

  脚本按**类名精确取体**，只比对 `class KitchenActionType` 的字符串值，`KitchenUiAction`（UI 入口键）与注释都不参与 ——
  **当前双向校验通过（6 项 / 0 失败，17 个 ActionType 一致）**。新增 ActionType 时两端同步后重跑。
- `verify_plugin_arch.py --client ../Client` 的默认布局已对齐 `Assets/Scripts/Kitchen/Plugins` 与 `Assets/Scripts/Kitchen/PluginFramework/KitchenPluginCatalog.cs`；**当前 C1 通过（11 个实现 == 11 条目录）**。
- `verify_asset_manifest.py` 不传 `--dir` 时会 SKIP，退出码 0；线上指针比对需要 `--server` + `--platform`。
- 玩法规则改完后，除上面几条还要跑 `python -m gameplay.verify`（离线自检，快但绕过 HTTP 与登录）
  与 `python test_gameplay_smoke.py <地址>`（端到端冒烟，含破产 / 收店两条结局）——**两条都要跑**。

## 十、部署与回滚

### 10.1 首次部署

在服务器上：

```bash
cd /path/to/Server
bash install_service.sh 80
```

`install_service.sh` 会：

1. 创建 `GP_APP_DIR`（默认 `/home/ubuntu/shuttercrisis`）与 `data/` 子目录；
2. 拷贝 `server.py` / `admin_client.py` / `admin_page.html` / `migrate_json_to_pg.py` / `services/` / `gameplay/`；
3. 安装 `shuttercrisis.service` 并 `systemctl enable`；
4. `systemctl restart`；
5. `curl /health` 健康检查。

`shuttercrisis.service` 关键配置：

- `User=ubuntu`，`WorkingDirectory=/home/ubuntu/shuttercrisis`
- `Environment=GP_MATCH_HOURS=24`、`GP_TOTAL_ROUNDS=12`、`GP_STORAGE=json`、`GP_PRUNE_INTERVAL=3600`
- `ExecStart=/usr/bin/python3 /home/ubuntu/shuttercrisis/server.py --port 80 --data-dir /home/ubuntu/shuttercrisis/data`
- `AmbientCapabilities=CAP_NET_BIND_SERVICE` 允许非 root 绑定 80 端口
- `Restart=always`，`LimitNOFILE=65535`
- `GP_ADMIN_KEY` 不要写进仓库，用 systemd drop-in 注入。

### 10.2 增量部署

本地：

```bash
cd Server
$env:GP_DEPLOY_HOST='10.0.0.1'    # PowerShell；bash 用 export
python deploy.py --pem ~/.ssh/id_rsa
# 或
GP_DEPLOY_HOST=10.0.0.1 python deploy.py --gen-key
```

`deploy.py` 会：

1. 连接主机；
2. 远端备份 `server.py` 与 `services/` / `gameplay/`；
3. 上传 `server.py` / `admin_client.py` / `admin_page.html` / `migrate_json_to_pg.py`；
4. 整包同步 `services/` 与 `gameplay/` 下全部 `.py`；
5. 远端 `py_compile` + `import server` 预检；失败即中止，旧版本继续运行；
6. 可选写入 `GP_ADMIN_KEY`（systemd drop-in）；
7. `systemctl restart shuttercrisis`；
8. 部署后验证 `/health` 与后台接口 403。

### 10.3 部署后验证

```bash
cd Server
python verify_deploy.py --host 10.0.0.1
```

`verify_deploy.py` 本地清点：

- `server.py` / `admin_client.py` / `admin_page.html` / `install_service.sh` / `shuttercrisis.service` / `migrate_json_to_pg.py` 是否都在；
- systemd 单元服务名、部署目录、`ExecStart` 指向；
- 交付物里是否残留旧地址 / 旧服务名 / 旧包名 / 旧玩法词。

远端验证（配置 `--host` 后）：

- `systemctl is-active shuttercrisis`；
- `/health` 返回 ok；
- 未带 `X-Admin-Key` 的 `/api/admin/stats` 返回 403；
- 部署目录存在 `server.py`；
- 旧服务名无残留。

### 10.4 回滚

- 代码回滚：`deploy.py` 在远端保留了 `server.py.bak.<时间戳>` 与 `services` / `gameplay` 的 tar 备份，可恢复到上一版本。
- 资源回滚：`services/asset.py` 在覆盖清单 / bundle 前做增量备份，可回滚到上一份清单与 bundle。
- 存储回滚：把 `GP_STORAGE` 切回 `json`；JSON 源数据在迁移时未被删除。
- 数据备份：`data/` 目录整体备份；`players/` 永不自动清理。

- `services/postgres_storage.py` 未在真实 PostgreSQL 上实测 SQL；上线前必须验证。
- `verify_action_contract.py` 按**类名精确取体**（只解析 `class KitchenActionType`），
  UI 入口键与注释不参与比对；当前双向校验通过（6 项 / 0 失败，17 个 ActionType 一致）。
