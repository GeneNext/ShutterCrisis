## 二、客户端编译检查

### 2.1 桩编译（不开 Unity）

```bash
python Tools/compile_check/compile_check.py --errors-only
python Tools/compile_check/compile_check.py --verbose
python Tools/compile_check/compile_check.py --assembly ShutterCrisis.Framework
python Tools/compile_check/compile_check.py --keep --verbose
```

期望：

- 退出码 `0`：全部自有程序集编译通过。
- 退出码 `1`：存在编译错误。
- 输出末尾会汇总错误；`--errors-only` 抑制进度日志。

失败先看：

1. `Tools/compile_check/compile_check.py` 的 `EDITOR_CANDIDATES` 是否指向本机团结引擎安装目录。
2. `Client/Library/Bee/artifacts/*/ShutterCrisis.*.rsp` 是否存在；缺失时脚本回退最小宏集合，结果可能不如编辑器精确。
3. 报错文件 / 行号；跨程序集错误通常说明 asmdef 引用缺了或方向反了。
4. 若报“找不到编辑器”，设置环境变量 `TUANJIE_EXE` 或修改候选路径。

**当前状态（2026-09-13 实测）**：桩编译、玩法自检、插件架构、协议契约、客户端静态、部署验证、
服务端用例、字体子集**全部通过**。剩余的功能性缺口是 `PanelManager.Back()`、
`SimpleButton.SetInteractable/SetVisible` 与 `AssetCdnConfig.asset` 的占位地址；
**面板 Prefab 需要在一次可用的 Unity 会话里跑「一键初始化工程」落盘**（枚举与 MVC 脚本已就位）。
唯一环境依赖是 `Tools/text_table/make_text_table.py` 需要 `openpyxl` 与源表。

### 2.2 真编译（团结引擎批处理）

```bash
python Tools/unity_check/unity_check.py --errors-only
python Tools/unity_check/unity_check.py --auto          # 推荐：让已开编辑器重编译
python Tools/unity_check/unity_check.py --log-only      # 只解析已有日志，历史快照
python Tools/unity_check/unity_check.py --timeout 1800
```

期望：

- `0`：无 error。
- `1`：有 error。
- `2`：环境问题（找不到编辑器 / 工程被另一个实例占用）。

失败先看：

1. `Tools/unity_check/unity_check.log`（脚本输出日志）。
2. `Client/Temp/CompileError/CompilationErrors.log`。
3. `%LOCALAPPDATA%\Tuanjie\Editor\Editor.log` 或工程 `Logs/`。
4. 若日志里有 `another Tuanjie instance` / `already open in another`，说明本次根本没编译，先关编辑器。

## 三、客户端静态自检

```bash
cd Server
python verify_client_static.py --client ../Client
```

当前检查项（`Server/verify_client_static.py`）：

1. 每个 `.cs` 都有 `.cs.meta`；
2. meta GUID 为 32 位十六进制且全局唯一；
3. asmdef 依赖图无环；
4. asmdef 引用可解析；
5. 项目内 enum 的成员引用存在（外部枚举无法判断，跳过）。

期望：退出码 `0`，输出“通过 N 项，失败 0 项”。

失败先看：

- 缺 `.cs.meta`：在 Unity 中让 Editor 重新导入，或确认新增脚本的 meta 已提交。
- GUID 冲突：大概率是复制文件时直接复制了 `.meta`，重新生成 GUID。
- asmdef 环：检查低层是否反向引用高层；公共编辑器工具应放 `ShutterCrisis.Editor.Common`。
- 枚举成员不存在：检查生成器是否只更新了枚举的一部分，或旧代码引用已删除成员。

**当前基座实测**：该命令当前退出码 `1`：

- FAIL “每个 .cs 都有 .cs.meta（196 个脚本）”，缺失 38 个，主要是 `TTAPIUpdate.cs` / `TTEditorTools.cs` / `TTUnityToolMergeTips.cs` / `TTEditorSupportProviderRegister.cs` / `TTMiniGameSupportProvider.cs` 等 `TT*` 文件。需要确认这些脚本是否属于应随工程提交的包内容；若属于第三方包，应从检查目录中排除。
- FAIL “枚举成员引用都存在（23 个枚举）”，误报 9 处 `eDataOperationType.Up/Down`。`eDataOperationType` 是 `CreatePanelEditorWindow` 内的嵌套枚举，静态检查器的正则解析范围有限；应在报告中人工确认后改进检查器。

### 5.1 玩法协议契约

```bash
cd Server
python verify_action_contract.py --client ../Client
```

当前检查：

1. 服务端注册表非空；
2. ActionType 无空名 / 无重复；
3. 每个 ActionType 都有可调用处理器；
4. 插件源码 `ACTIONS` 字面量声明的项都已注册到运行时；
5. 有客户端常量文件时做双向校验；否则打印 `[SKIP]` 并退出码 0。

期望：`通过 N 项，失败 0 项`，退出码 0。

失败先看：

- 服务端：哪个 ActionType 没有处理器 / 未注册 / 重复声明。
- 客户端：`--client` 与 `--action-type-file` 是否指到正确文件；服务端 ActionType 与客户端常量是否一一对应。

**当前实测（退出码 0）**：

                          'SetPrice','ShootOrder','StartQuarrel','SubmitReview','TakeOrder',

[PASS] 注册表非空（至少一个行动）

## 六、字体子集与文案表

### 6.1 字体子集

```bash

python Tools/font_subset/make_ui_font.py --stats
python Tools/font_subset/make_ui_font.py --report-missing
```

退出码含义：

| 退出码 | 含义 | 先看哪里 |
| :--- | :--- | :--- |
| `0` | 生成成功 / 校验通过 | — |
| `1` | `--check` 发现产物缺字 | 输出里的缺失字符；重跑生成 |
| `2` | 产物 `ShutterCrisisCN.ttf` 不存在 | 先执行生成 |
| `3` | 文案里出现 Emoji / 装饰符号 | 输出里的文件和字符；按建议改成 `× ! > ->` 或美术图标 |
| `4` | 源字体缺字 | `--report-missing` 的字符与文件；换字或换源字体 |

失败先看：

- `Client/Assets/Resources/UI/Fonts/ShutterCrisisCN.ttf` 是否存在且新鲜；
- 源字体候选是否存在：脚本按 `SOURCE_CANDIDATES` 顺序选**第一个真实存在**的文件，缺文件会跳过而不是崩。
  当前顺序为 ① `Client/Assets/Fonts/ZCOOLKuaiLe-Regular.ttf`（OFL，可随包分发）→
  ② `Client/Assets/Fonts/msyh.ttc`（微软雅黑，**专有字体，不可再分发**）。
  **本仓库当前缺①**，所以实际会走②，脚本会打印警告；
- 微软雅黑是专有字体，**用它生成的产物只可本地预览，不得随发行包提交/发布**；
  正式出包前必须补上①（OFL 字体）并重跑生成。补上后无需改脚本，会自动优先用①；
- 扫描语料按“UTF-8 with BOM”读取（用 `utf-8-sig`）；BOM 不会被当成界面字符；
- 新增中文文案后必须重跑生成并提交产物。
