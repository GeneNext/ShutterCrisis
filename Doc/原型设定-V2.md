## 一、设计目标与不变量

### 1.1 为什么要 V2

V1 已把「报表经营」完整落地：现金流、订单、定价、员工、场地、广告、AI 冲击、吵架、锐评——
但玩家体验是**在菜单里点按钮、看数字变化**。缺三样东西：

- **造物爽感**：买地、装修、升设备全是"数字 +15%"，没有"我把店造大了"的实感——
  老板的核心幻想被报表埋没了；
- **画面感**：店里没有"真的人"在跑动，经营结果看不见过程；
- **情感锚点**：员工是一行行数据，没有"我的人"的感觉；客人差评凭空出现，看不到成因。

操作上，一天的心智负担集中在 8 个页签 + 模态弹窗拦截，例行决策重复且分散。

### 1.2 不变量（红线，V2 不得破坏）

| 不变量 | 内容 |
|---|---|
| 现金流唯一致死 | 只有破产（现金 < 0 且连续 7 天净现金流为负）会结束游戏；**有限的逃生门见 §6.8 破产防线** |
| 无胜利条件 | 无限经营，玩家自行决定何时收店 |
| 服务器权威 | 一切数值判定在服务端，客户端只投影（[`分层与命令驱动.md`](分层与命令驱动.md)） |
| 确定性随机 | 玩法判定不用 `random`（随机事件库除外），存档必须可复现、离线可推进 |
| 命令驱动验收线 | `KitchenCommandRunner` 必须能在无任何 Panel/View 时跑完「开新局 → 晨会 → 排期 → 营业 → 结算」 |
| 商业化边界 | 广告 / 付费只解锁**救命机会**与便利功能，**不卖经营数值**；救命有冷却与代价，不无限续命（§6.8） |

### 1.3 四个设计支柱（按阶段顺序）

1. **老板的反馈循环**（主循环，L1，第一阶段地基）：老板的每个行动（买地/装修/招人/升设备/定价/接单/加薪）
   都要在当天、最好当时段，得到**看得见的反馈**（钱、人、店、星级）——行动 → 反馈 →
   下一个行动，这个环就是主循环（§2.3）；
2. **看得见的店**（L2，第二阶段）：客人像双点医院的病人一样走管线，队列是待变现的现金流，
   老板的每个决策立刻翻译成钱和人；
3. **员工按成长空间分两类**（L3，与第一阶段同期交付基础件）：普通员工（无成长空间）按去留两因子管理——
   对他们好、或者盈利非常好，他们就会留下；成长型员工**共进退**（学徒 → 骨干 →
   大师 → 合伙人），是长期投资对象（§5.2）；
4. **顺手的操作**（贯穿各阶段）：晨会聚决策、收件箱替弹窗、一键过例行——例行一天 3 次点击以内。

### 1.4 上瘾模型：引擎是复利，动线是代币与糖衣

> 双点医院的"治疗循环上瘾"是常见误读（详见 [`原型调研-双点医院.md`](原型调研-双点医院.md) §2.1 注）。
> 本作把成瘾结构显式化，作为系统取舍的标尺：

| 角色 | 承担者 | 设计要求 |
|---|---|---|
| **引擎**（成瘾核） | 现金流复利：接单赚钱 → 再投入设备/房间/员工 → 单价与吞吐提升 → 赚更快；店铺等级天梯提供目标梯度 | V1 已有引擎；V2 用天梯把"距下一目标"组织成每日可见刻度（§7.3 晨会进度条） |
| **代币**（高频小奖） | 每单离店即结：钱 + 满意度 + 口碑 + 小费 + 照片质量分，音画同步 | 动线层是代币发放器；结算延迟会直接削弱循环（禁止"攒到日晚一起结"） |
| **糖衣**（留客质地） | 小人演出、头顶气泡、等待的客人是"看得见的收入流" | 让两次购买之间的等待有内容；糖衣不产数值，但决定体验冷热 |
| **张力**（防挂机） | 差评舆情、员工离岗、加急插队、AI 冲击——引擎有失速可能 | 复利不能无风险，否则退化成放置游戏 |

**由上瘾模型导出的硬规则**：

1. **任何再投入必须有肉眼可见的增量**——升化妆区 2 级要看到第二个化妆位真的开始上人，
   而不是数字 +15%。可见性不足的升级 = 白做；
2. 大额购买是**大奖时刻**：攒钱 → 选择（买什么/放哪里/派谁）→ 立即看到它接入运转——
   购买流程本身就是玩法，不是菜单操作；
3. 设计资源优先级：升级的可见反馈 ≈ 目标临近感 > 演出华丽度。演出是糖衣，不是引擎；
4. **无脑最优解测试（上线门禁）**：任何决策维度（定价档 / walk-in 档 / 排班 / 投入项）上线前
   必须验证"不存在一招通吃的全局最优"——双点医院的定价因"全部 +20% 无视价格声誉"沦为摆设
   （[`原型调研-双点医院.md`](原型调研-双点医院.md) §三 F4）。发现无脑最优 → 该维度回炉，
   直到至少三档各有明确的适用场景（客群 / 阶段 / 风险偏好）。

## 二、玩法模型：三层按阶段适配，反馈循环先行

### 2.1 阶段适配原则

本文件不按"谁重要、谁不重要"划分系统，按**系统服务于哪个阶段**组织：

- **反馈循环先行**：老板"行动 → 即时反馈"的环（买地/装修/招人/升设备/加薪 → 钱进账、
  客流变、店变大变好、人留下）是所有阶段共同依赖的地基，必须最先成立、最先做扎实；
- **动线可视化随后**：反馈要"看得见"——动线层把每个决策翻译成钱和人；
- **员工按成长空间分两类**：普通员工（无成长空间）按两因子去留管理，不必纠结；
  成长型员工可以**共进退**（学徒 → 骨干 → 大师 → 合伙人），其深度内容（志向/关系）
  属于 P2 阶段（§5.8）。

每套系统都有它的阶段：先做后做取决于依赖顺序与验证顺序，不取决于重要性。

一句话定位：**老板行动的即时反馈是主循环；动线让反馈看得见；员工基础件管去留——
对他们好或盈利好，他们就会留下，深度内容按阶段展开。**

### 2.2 三层模型（重排后）

| 层 | 阶段定位 | 玩家做什么（爽点来源） | V1 现状 |
|---|---|---|---|
| **L1 老板操作层（反馈循环）** | 第一阶段：地基，所有阶段的公共依赖 | **买地**（向右/向后/二楼）· **装修**（形态三段：化妆桌 → 化妆室 → 艺人独立化妆间；氛围分 P2）· **招人**（招聘/培训专精/加薪挽留/排班）· **升设备**（具象线：背景纸 → 无影棚 → 商业影棚；灯光到顶牌；相机到"哈神"）· **定价接单**（五档定价/walk-in 策略/客群进化）· **升星**（五维门槛 → 评审仪式 → 店牌换新）· **资产运作**（卖设备折价/救命大单/被动收缩/贷款 P2）——**每个动词都有当天可见的反馈** | 骨架已有（扩张/设施/员工/定价），**缺反馈包装：无具象、无形态、无天梯、无仪式——V2 的主要工作量在这层** |
| L2 店内动线层（双点医院移植，主参考） | 第二阶段：反馈的可视化 | 把老板的每个决策**立刻翻译成钱和人**：队列 = 待变现资产、客人头顶客单价、流失 = 红字飞走、热力图 = 下次该买什么 | 无（订单三态直进直出） |
| L3 员工层（按成长空间分两类） | 普通员工管去留，成长型管进阶 | 员工**可以流动**，**对他们好或盈利非常好就留下**（两因子，§5.3）；**按成长空间分两类**：普通员工（无成长空间）就近补招不必纠结；成长型员工**共进退**——学徒 → 骨干 → 大师 → 合伙人（§5.4），患难不散 | 仅有 Mood/Loyalty/Trait 数据行 |

### 2.3 主循环 = 老板的反馈循环

```
老板行动（买地 / 装修 / 招人 / 升设备 / 定价 / 接单 / 加薪挽留…）
   ↓ 即时反馈（当天，最好当时段）
钱：客单入账、流失红字、现金流预测更新
人：队列长短、客人满意度、传播事件
店：面积 / 形态 / 设备的可见变化、星级进度、员工去留
   ↓ 反馈驱动下一个行动（每个负面反馈必须附"怎么改"，§8.5）
```

主循环不是"操作"这个动作本身，而是**行动与反馈之间的间隔足够短、归因足够清**：

- 任何老板行动必须在**当天**给出看得见的反馈；做不到当天的（如扩张工期），要有阶段性
  可见进度（施工中的围挡、倒计时）；
- 反馈必须**可归因**——玩家能说清"这个结果是老子哪个决定造成的"；
- 反馈延迟超过一天的，必须在周反思会补账（§8.5），不留糊涂账。

### 2.4 老板动词清单（每个动词都已在本文件有落点）

| 老板动词 | 爽点 | 落点 |
|---|---|---|
| 买地 | 向右/向后/二楼；扩张确认时展示"新增日支出 vs 新增日收入"对照 | §7.2 / §7.4 |
| 装修 | 空间形态三段改造（含工期与容量跳档）、布局模板复制、氛围分（P2） | §6.6 / §4.3 |
| 招人 | 招聘看履历（普通员工随招随有，**成长型低概率遇到**）、培训专精资格、想走的**加薪挽留**、排班布阵 | §5.1~5.4 |
| 升设备 | 三条具象升级线 + 影射命名（"哈神"到手的那一刻） | §6.6 |
| 升星级 | 五维门槛 → 升级评审全屏仪式 → 新客群/新解锁/新目标 | §七 |
| 定价接单 | 客群从"砍价狠差评多"进化到"指名委托、钱不是问题" | §4.4 / §7.2 |
| 资产运作 | 卖设备折价 40%、救命大单（广告/付费）、被动收缩 | §6.8 |
| 放权 | 4★ 起只出创意 brief，付钱交团队执行——老板的终局形态 | §4.7 |

### 2.5 两层如何服务主循环（耦合关系）

```
            ┌──────── 老板的反馈循环（核心，§2.3）────────┐
            │ 行动（买/装修/招人/升设备）→ 即时反馈 → 再行动 │
            └────────┬────────────────────────┬─────────┘
     反馈可视化（钱和人看得见）│                │产出上限与去留
            ┌────────▼────────┐      ┌────────▼────────┐
            │ L2 动线（仪表盘）  │      │ L3 员工（流动产能）│
            │ 队列 = 钱        │      │ 技能 / 精力      │
            │ 流失 = 红字飞走   │      │ 对他们好/盈利好→留 │
            └────────┬────────┘      └────────┬────────┘
                     └── 反馈可见 → 告诉老板下一步"买什么" ──┘
```

具体互锁：员工状态决定工位效率（累的化妆师 = 化妆变慢 = 队列变长）；动线失败产出经营成本
（等待过久 → 差评/退款/吵架，客服事件有了看得见的成因）；资金购买产能与福利；品牌与 AI
塑形客流形状（网红品牌 = 脉冲客流 = 动线压力测试）；员工去留由待遇与盈利决定（想走可加薪挽留）。

设计原则（不变）：**L2/L3 的每个负面结果都必须能被玩家追溯到成因**（点开一条差评，能看到
"这位客人等了 3 个时段、化妆师中途离岗休息"）——但归因的终点是**指导老板的下一个购买决策**，
不是让玩家去当保姆。

## 三、一天的新结构（四幕）

### 3.1 四幕时间轴

| 幕 | 状态 | 玩家做什么 | 系统做什么 |
|---|---|---|---|
| 晨会（早） | 暂停 | 看简报（预约预览/员工预警/现金流预测/待办），确认定价、广告、排班、排期指派；可全用推荐值一键应用 | 生成今日预约池与 walk-in 预估 |
| 营业（白天） | 1x/2x/4x/跳过，随时暂停 | 看/干预现场：亲自微操拍摄、处理加急插队、安抚员工、响应事件收件箱 | 按时段逐段结算动线（见 3.4），排队、离岗、微操判定 |
| 晚结算（晚上） | 暂停 | 看日报 + **动线复盘**（当日瓶颈热力：哪个工位等待最长） | 现金流结算（order=100 不变）、满意度汇总、客服事件成因归档 |
| 深夜（可选） | 暂停 | 修图加班、外出采风（P2）、发线上内容 | 员工去留意愿结算（谁想走，次日晨会预警） |

### 3.2 与 V1 的映射

- V1 的「一天 = 一个回合、NextDay 一把结算」**保留为服务器的权威节奏**；
- V2 把"白天"从黑盒拆成 **8 个时段的离散结算**（沿用 `_studio.SlotsPerDay()`，
  当前 8 + 接待区等级 − 1），每时段推进一次动线状态；
- 「结束营业」按钮从 Main.Home 移到营业幕结束时点，或保持原位——两者等价，命令不变（`NextDay`）。

### 3.3 幕间切换的体验规则

- 晨会与结算幕**强制暂停**，营业幕默认 1x；
- 营业幕中出现"立即处理"级事件（吵架被触发、设备故障）→ **自动暂停 + 收件箱红点**，玩家点开
  才继续，不打断者可设置忽略；
- 任何时刻可存档退出（已满足：服务器自动存档）。

### 3.4 关键工程决策：「实时」是演出，不是模拟

服务器是回合制 + 离线推进 + 确定性随机，**不能**做每帧模拟。V2 的解法：

1. 服务器按**时段**离散结算动线（每时段：到店 → 各工位服务/排队 → 离岗恢复 → 满意度变化），
   产出当日 `Flow` 日志（见 §9.3）；
2. 客户端把 `Flow` **演出**成小人走动动画，速度控制（1x/2x/4x/跳过）只影响演出；
3. 离线推进：服务器直接算完全部时段，客户端下次登录只看结果或快进回放；
4. 动线内部判定（walk-in 抽取、到店波动）用 `(Round, slot)` 作种子的 LCG（沿用 `staff._Roll`
   模式），随机事件库继续走 `random`（其语义即随机）。

这样三条红线（确定性 / 离线推进 / 命令驱动验收线）全部保住。

## 四、L2 店内动线层（双点医院移植，主参考）

### 4.1 双点医院 → 照相馆 映射表（主参考）

| 双点医院 | 本作对应 | 移植后的变化 |
|---|---|---|
| 病人（挂号→诊断→治疗→结算） | 客人（预约单 / walk-in 散客） | 客人带订单类型与耐心值（沿用 `customer_tone` 4 种）；**每单离店即结满意度与小费**，不等日晚 |
| 前台挂号（助理） | 接待/等待工位 | 座位数 = 接待区等级；站着的客人满意度掉得快 |
| 诊断把握度 % | **需求把握度**（咨询环节产出） | 把握不足 → 重拍率/客诉上升；由客服技能、顾客性格、接待/咨询等级决定 |
| 诊室（全科 → 专科转诊） | 工位管线（咨询 → 化妆 → 影棚 → 选片 → 修图 → 交付） | 各环节占 0~2 时段，按订单类型跳过不需要的环节 |
| 医生疲劳 / 要加薪 / 资格 | 员工精力 / 忠诚 / **培训专精资格**（L3） | 见第五节 |
| 护士 / 前台助理 | 客服岗 | 排队时安抚，减缓满意度衰减 |
| 勤杂工（扫地/浇水/维修） | 助理岗 | 整理道具 / 补耗材 / 维护设备；环境脏乱肉眼可见地积累 |
| 紧急事件 | 加急单 | 可插队，代价 = 其他客人满意度 |
| 传染病（防控或瞒报） | **差评舆情**（P1） | 负面情绪在候诊客人间扩散；玩家可即时补偿安抚（防控），也可冷处理赌不发酵 |
| VIP 巡视打分 | VIP 探店（升级现有"明星到店"事件） | 按店内氛围与动线顺畅度打分，给口碑/粉丝奖励 |
| 年终评奖 | **年度评奖**（P1） | 年度照片 / 口碑 / 网红店评选，给钱/粉丝/技能点；为无限经营供阶段目标感 |
| 走廊堵塞 / 行走距离 | 动线交叉 / 布局差 | 等待时间上升 |
| 医院声望 / 星级目标 | 口碑 / 品牌调性 + **里程碑成就** | 星级关卡制与"无限经营"冲突 → 改里程碑：达成给奖励，不上锁不结束；口碑改为影响**到店曲线形状**（见 6.4） |
| 房间面积/装饰加成、房间模板复制 | 氛围分（P2）+ 布局模板复制（P1） | 面积与装饰给质量加成；布局可整片保存复制 |
| 研究页 / 营销活动 | 设备升级线 / 既有 6 广告渠道 | 不新增独立系统，避免铺开 |

### 4.2 动线管线与工位定义

7 个工位 = 「分区（已有 facility）+ 岗位（已有 staff 目录）」的组合，**不新增设施目录键**，
只把现有 13 项里的分区解释成"工位容量"：

| 工位 | 依赖分区（facility 键） | 依赖岗位 | 占时段 | 缺失/拥堵后果 |
|---|---|---|---|---|
| 等待 | 接待区 | 客服 | 0~1 | 站着等，满意度快速衰减 |
| 咨询 | 接待区（高等级） | 客服 | 0~1 | 跳过 → 需求把握度低 → 重拍率/客诉上升 |
| 化妆 | 化妆区 | 化妆师 | 1 | 无 → 上镜度低、拍摄难度高 |
| 拍摄 | 棚拍区 | 摄影师 | 1~2 | 无 → 无法交付（核心工位） |
| 选片 | 接待区 | 客服 | 0~1 | 跳过 → 客人纠结，占用后续时段 |
| 修图 | 后期区 | 修图师 | 0~1 | 无 → 交付延迟、次日占用产能 |
| 交付 | 接待区 | 客服 | 0~1 | 阻塞 → 无法收款进当日收入 |

- 订单类型决定走哪些环节（证件照：等待 → 拍摄 → 交付；婚纱：全环节）——订单目录新增
  `stations` 字段描述路径与各环节耗时系数；
- **需求把握度**（对标双点医院"诊断把握度"）：咨询环节结束时产出 0~1 的把握度，决定重拍与
  客诉概率；高技能客服 + 契合顾客性格的话术提高把握度。双点医院靠"诊断"转动核心循环，
  本作由"咨询"承担同一个旋钮；
- 储物区 / 展示区 / 灯光等设备项**不在动线上**，维持 V1 的被动加成（质量上限/效率/信任度）；
- **新增 1 个 facility 条目：休息区**（员工恢复与福利，见 §5.5），目录变 14 项。

### 4.3 队列、吞吐与布局

- **并发 = 分区等级，形态给跳变**：化妆区 2 级 = 同时 2 位客人上妆；空间形态改造
  （化妆桌 → 化妆室 → 艺人独立化妆间，§6.6）让并发与隐私加成跳档，且是高星客群的接单门槛；
- 客人按预约时段到店；目标工位忙 → 排队（FIFO，加急单可插队）；等待每满 1 时段扣一次满意度
  （量由顾客耐心值缩放）；
- **员工跨工位移动耗时**（P0 为 0.25 时段的固定系数，P1 起按分区距离）：
  休息区放在工位区旁边 = 恢复来回成本小 —— 这是布局策略的第一课；
- **分期引入布局自由度**：
  - **P0**：固定分区模板（分区沿 V1 网格自动排布），玩家只调"分区等级 + 排期"；
  - **P1**：分区/设施**拖拽摆放**（演化稿设施表带占格 1~4 格），客人区与员工区重叠 → 干扰系数；支持**布局模板保存与整片复制**（对标双点医院的房间复制 QoL）；
  - **P2**：家具级自由摆放 + 氛围分（对齐 V1 扩展点"decor 目录 + `St["Furniture"]`"）。

### 4.4 walk-in 分流（新决策）

预约客（排期锁定）与散客（walk-in，双点医院式随时进门）的比例是**策略选择**：

| 档位 | 效果 | 适合 |
|---|---|---|
| 预约优先 | 散客配额低，动线稳，收益可预期 | 高端/婚纱路线 |
| 均衡 | 各半 | 默认 |
| 来者不拒 | 散客配额高，忙时排队严重、差评风险高，闲时吃满产能 | 亲民/网红路线 |

新行动 `SetWalkInPolicy`（Option = 档位 id）。品牌调性影响散客质量（网红 → 打卡散客多）。

### 4.5 加急与团客

- **加急单**（双点医院的紧急事件）：高价/高口碑奖励，可插队，被插队的客人满意度扣减；
  拒绝也有代价（口碑小扣）；
- **团客**（一家人/企业团建拍摄，对应随机事件"客人带一家人来"）：一次占多工位、多人同时
  化妆/拍摄，是布局与并发压力的峰值测试。
- **差评舆情**（对标双点医院传染病，P1）：负面情绪会在候诊客人间**扩散**（等待越久扩散越快）；
  玩家可即时补偿/安抚（防控），也可冷处理赌它不发酵——发酵则口碑批量受损、当日客流下滑。

### 4.6 客人即可视化现金流（留存与传播）

> 设计母题：**每位客人都是一笔行走的现金流**。证件照客人是小额零钱，写真客人是纸币，
> 艺人团队是金条——服务没到位他走了，不是"扣分"，是**看得见的钱飞走了**。

**可视化规则**：

- 客人头顶挂客单价标签（金额 + 客群图标），动线演出中一眼看出"今天店里流动着多少钱"；
- 结账离店：金额飞入顶栏现金，配小费/传播气泡（"下次还来""我要发小红书"）；
- **流失离店**：金额变红飘走并弹流失成因（"等了 3 个时段""照片显胖没谈拢"），计入当日
  流失合计——日报的"今日流失 ¥1,240"就是这些红色数字的总和；
- 排队长度 = 现金流可视化：队列就是"待变现资产"，堵塞就是"变现减速"。

**留存度与传播度（数值提案，目录化调参）**：

```
单客满意度 S = 技术水平（质量分/设备线/专精资格） × 服务水平（等待时长/需求把握度/陪同配置/环境）
留存（复购）概率 = 20% 基础 + S × 40% + 客群修正（家庭客 +10%，艺人团队 −10%）
传播概率     = 5% 基础 + (S − 0.6) × 30% + 网红客群 ×2 + 爆款作品加成
```

- **服务好 → 概率触发传播**：「分享好友」（3 天内自然客流 +2~5 的脉冲）与「发布平台」
  （粉丝 +N，按作品质量）——把口碑从抽象数值变成看得见的客流事件；
- 传播与留存**全部由确定性 LCG 在离店时判定**（离线推进可复现）；
- 反向保留：**无理取闹的客人永远存在**（碰瓷型/蛮横型客群 + 差评威胁），吵架系统是现金流
  的"防损"手段，不是噪音——赢了保住这单钱，输了钱和口碑一起走。

### 4.7 服务分级：陪同、布景与放权

服务内容随店铺等级进化——**低等级拼体力，高等级拼想法**：

| 服务形态 | 解锁 | 化妆侧 | 摄影侧 | 体力/微操 |
|---|---|---|---|---|
| 带路快拍 | 1★ | 无陪同（客人自理，妆效一般） | 摄影师带路 + 按快门 | 体力消耗低，零微操 |
| 标准写真 | 2★ | 化妆师 1 对 1 | 摄影师 + 助理铺基础背景（轻度体力） | 轻引导：拍摄中选话术（影响需求把握度） |
| 全程陪同 | 3★ | 化妆师 + 助理陪同（满意度显著 +） | 摄影师**与助理团队布置场景、含拆装**（重度体力——排班必须留恢复余量，精力管理成为排班核心） | 引导为主 |
| 团队交付 | 4★ | 造型小班底 | **玩家只出"创意 brief"**（选主题/参考/预算）→ 付钱交团队执行，质量取决于专精资格与关系默契 | 无日常微操；看结果演出 |
| 顶级大片 | 5★ | 全套造型班底 | 同上，顶级团队 + 指名客 | 深度微操只在锐评时刻出现（见 §6.7） |

- 陪同人数是**服务等级的显性表达**：客人看到"一个化妆师带俩助理围着转"，满意度与传播
  概率同步上调——多雇的人直接翻译成客单与口碑；
- **形态是服务分级的物理前提**：3★ 全程陪同需要房间级化妆区，5★ 艺人班底必须先改造成
  艺人独立化妆间（§6.6）——先有房间，才谈得上服务形态；
- 布景拆装的重体力把 L3 精力系统变成排班约束：接大单前要让摄影师休息满，或加派助理分摊；
- 4★ 起的"放权"是自信心的终局形态：老板的价值从动手变成**判断与创意**，与 §5.6 管理风格
  （亲力亲为 → 甩手掌柜）同一条成长弧。

## 五、L3 员工层（按成长空间分两类）

> **分类原则**：按**员工自身的成长空间**划分，与店开到第几天无关——"前期员工"指的是
> **没有成长空间的员工**，不是创业期的员工。普通员工按两因子去留管理，不必纠结；
> 成长型员工可以**共进退**，是老板的长期投资对象，深度内容只为他们存在。

### 5.1 员工是什么

- 员工 = 带技能的产能：技能 + 专精资格决定质量上限，精力决定当日产出；
- **流动是常态**：离职是经营节奏的一部分——「招聘」与「加薪挽留」是常规经营动词；
- 去留判定每天深夜结算一次（§3.1），想走的人提前一天预警，晨会可见；
- **为谁纠结**：普通员工不纠结（就近补招），成长型员工值得挽留与投资——两类员工的
  差异是本章的核心（§5.2）。

### 5.2 两类员工（按成长空间）

| | 普通员工（无成长空间） | 成长型员工（有成长空间） |
|---|---|---|
| 特征 | 技能上限 2~3 级、无可学专精或仅一门基础；市场供给充足，随招随有 | 技能可练到 5 级、可习得多门专精资格；市场稀缺——招聘贵、看运气（猎头/内推/封神后自荐） |
| 去留 | 两因子（§5.3），**不必纠结**：走了就近补，挽留只在顺手时 | 两因子 + **第三因子：成长空间**（"这店能让我变强"）；**患难不散**——短期亏损不赶人走 |
| 深度内容 | 永远不进（不做志向/关系类内容） | P2 阶段启用（志向/关系只对成长型开放，§5.8） |
| 定位 | 产能的常规补充 | 店的长期资产：学徒 → 骨干 → 大师 → 合伙人（§5.4） |

招聘市场据此分层：普通员工常驻可招；成长型员工低概率出现（确定性 roll），遇到就是机会。

### 5.3 去留规则

```
去留意愿 = 对他们好（工资不低于行情 + 排班不压榨 + 有休息区/团建福利）
         + 盈利非常好（现金流健康/增长 → "店有前途"加成）
         + [成长型专属] 成长空间（在店能学专精、接高阶单、被指名）
```

- 意愿 ≥ 60 留下；40~60 **想走预警**（晨会红点，可 `RetainStaff` 加薪挽留一次）；
  < 40 次日离职（产能空缺，重新招聘）；
- **敏感性差异**：普通员工对盈利波动敏感（店不行就走）；成长型对成长机会敏感、
  对短期波动耐受——危机期（§6.8）走的是普通人，**走不散的是班底**；
- 离职影响聚焦经营面：产能空缺 + 招聘成本；"带走客户"类惩罚属 P2 可选项，基础阶段不做。

### 5.4 成长型员工的进阶（共进退的兑现）

| 阶段 | 条件 | 身份变化 |
|---|---|---|
| 学徒 | 成长型入职 | 可培养对象，培训效率 + |
| 骨干 | 技能 3 级 + 首门专精资格 | 同班可带普通员工（效率 +）；去留意愿获得成长加成 |
| 大师 | 技能 5 级 + 双专精资格 | 高端订单与指名客的人才门槛；满足 5★ 天梯的"大师资格 ≥2"条件 |
| 合伙人 / 店长 | 大师 + 里程碑（P1 交付） | 终局绑定：不离职、分利润、大师班底核心、可代老板顶岗（§4.7 放权线的承接者） |

这条进阶线是五维门槛（§7.2）里"专精资格员工 ≥1 / 大师资格 ≥2"的具体来源——
**天梯要求的从来不是人头，是成长出来的人**。

### 5.5 性格特质（风味，不做系统）

保留 V1 的 5 种 trait（出错率修正 + 风味文案），扩展到 10 种列 P1 可选；特质**只影响数值
与头顶气泡文案**（急性子出错率高、社牛接待加成、夜猫子排班高亮黄金时段），不驱动行为剧情。

### 5.6 自主行为（最小集）

- 精力 < 30 自动离岗休息 1 时段（队列积压）——这是排班要留余量的原因，也是休息区/布局的价值；
- 社牛在队列旁和客人聊天，减缓烦躁（被动加成）；
- 其余需求类自主行为（觅食/社交等）属 P2 阶段内容，基础阶段不启用。

### 5.7 老板（玩家）也是人（属 L1）

- 老板化身有**精力条**：亲自微操（拍摄/修图）耗精力，深夜加班 → 次日效率减益；
- **管理风格**二选一（可随时切换，影响品牌推力）：亲力亲为（省工资、微操加成强、自己精力消耗大）
  vs 甩手掌柜（店内自动运转、品牌"专业"推力、依赖员工质量）；
- 老板不占员工工资位，但亲自顶岗时 = 占用一个工位并发。

### 5.8 后续阶段内容（P2）

志向、关系网（师徒/竞争/恋爱/敌对）、需求五维等深度内容，**只对成长型员工启用**；
进入条件：核心循环上线并验证后。进入前相关条目不进目录、不进状态契约，避免半成品状态。

### 5.9 确定性约束（不变）

去留判定、自动休息、技能成长、招聘 roll 全部走**确定性 LCG**（种子由 `Round` + 对象 id 派生，
沿用 `staff._Roll` / `_RollFloat` 模式），离线推进可复现；客户端只演出，不自算。

## 六、内容与玩法重组总表

### 6.1 系统互锁表（"重新组合"的核心）

| A × B | 涌现结果（玩家可感知） |
|---|---|
| 动线 × 员工需求 | 化妆师中途离岗休息 → 队列堆积 → 客人等待 → 差评风险（现场看得见） |
| 招人 × 流动 | 员工流动是常态 → 招聘/加薪挽留是常规经营动词；挽留成本 vs 重新招聘的市场价权衡 |
| 成长空间 × 去留 | 普通员工盈利敏感（危机期先走）；成长型成长敏感、**患难不散**——班底是熬过危机（§6.8）的本钱 |
| 品牌 × 动线 | 网红调性 → 打卡散客脉冲式到店 → 必须用 walk-in 策略与接待容量接住流量 |
| AI 冲击 × 岗位 | 订阅 AI 修图 → 修图环节自动化 → 修图师产能闲置 → 转岗或自然流动（志向剧情属 P2，仅成长型员工） |
| 锐评 × 排期 | 爆款作品 → "指名复购客"（新顾客子类，锁定特定摄影师，排期必须留档期） |
| 吵架 × 动线 | 等待 ≥ 2 时段成为吵架新触发源；老板替员工出头赢吵架 → 该员工心情大涨 |
| 客服事件 × 动线 | 客服事件**由动线失败驱动**（见 6.2），不再凭空每 3 天一条 |
| 场地 × 员工 | 休息区是福利与恢复点（去留因子之一）；布局决定"离岗来回成本" |
| 老板精力 × 微操 | 亲自拍大单收益高，但连轴转 → 次日全店决策效率降（晨会推荐失效一轮） |
| 服务分级 × 体力 | 3★ 场景布置含拆装重耗体力 → 接大单前必须排休或加派助理（§4.7） |
| 留存传播 × 技术服务 | 质量高 + 等待短 → 分享/发布触发 → 自然客流脉冲 → 动线吃流量（好压力） |
| 周反思 × 流失可视化 | 周报流失 Top3 成因 → 指导下一周投入方向（与 §7.4 投资表闭环） |

### 6.2 客服事件：从"随机弹窗"改为"有成因的结果"

V1：每 3 天固定挂一条客服事件（`SERVICE_EVENT_EVERY_DAYS`）。
V2：**主要由动线失败触发**——等待 ≥ 2 时段 / 质量低于该客类型阈值 / 员工出错当日命中，即入
收件箱；每 5 天保底一条（防极端幸存者局面）。事件文案携带成因摘要（"等了 3 个时段、修图延迟 1 天"）。

### 6.4 品牌调性 → 客流形状（品牌系统动线化）

| 调性 | 到店曲线 | 动线含义 |
|---|---|---|
| 亲民 | 平稳、散客多 | 吃接待容量，走量 |
| 专业 | 低频高价、预约为主 | 吃质量与并发，排期密度低 |
| 艺术 | 极低频极高价 | 全环节慢速，锐评联动 |
| 网红 | 脉冲（爆款后暴增） | 压力测试：接待/化妆瞬时过载 |
| 硬气 | 稳定、讲理客 | 少而精，吵架胜率收益高 |

AI 冲击重述：**AI 店 = 零动线成本的对手**（没有现场、没有等待、也没有体验）。玩家的护城河 =
L2 的现场体验 + L3 的人的关系。不可替代度改由「动线满意度累积 + 员工关系深度 + 实体交付」
三项加权（`market.py` 调参，公式不变结构换权重来源）。

### 6.6 设备与空间的具象升级线（形态改造 + 影射命名）

升级不能只是"+15% 画质"的数字——**每条设备线与每个功能分区都要有肉眼可见的形态进化**
（对齐 §1.4 "升级必须可见"硬规则）。设备走"具象三阶段"，空间走"形态三段"，同一套规则。

**设备线（具象三阶段）**：

| 设备线 | 入门（1~2★） | 专业（3~4★） | 顶级（5★） |
|---|---|---|---|
| 背景系统 | 背景纸（越买越宽的卷筒纸，换色靠手撕） | **无影棚 + 主题布景**（背景墙/道具架，可换主题） | **商业影棚 + 顶级定制布景**（整面实景搭建，按订单定制） |
| 灯光 | 杂牌灯架（"亮就行"，色温漂） | 专业影室灯（宝富图/爱灵级，可控光比） | 顶级超贵品牌（外拍电箱、全无线控制） |
| 相机 | 二手入门机（对焦靠缘） | 中端全画幅（加能/尼辰/索灵级） | 旗舰中画幅（**哈神**级——玩家一眼认出"这是顶配"） |
| 后期 | 家用电脑修图 | 专业修图工作站 + 色准屏 | 团队流水线 + AI 辅助（订阅权衡） |

**影射命名规则（合规前提下的"梗"）**：

1. 与现实商标**不同名**，允许音近变体（哈苏 → **哈神**；佳能 → 加能；尼康 → 尼辰；
   索尼 → 索灵；Profoto 保富图 → 宝富灯；Elinchrom 爱玲珑 → 爱灵灯）；
2. 不使用任何商标图形、Logo、外观专利造型；目录文案**不宣称"某某同款"**；
3. 同类目成体系（相机用"X 神/X 能/X 灵"，灯光用"X 灯"），玩家能会心一笑但构不成混淆；
4. 上线前过一次法务视角自查（行业惯例做法，风险低但要看渠道要求）。

设备目录（`facility`）条目增加 `tierNames`（各等级的具象名与外观描述），等级解锁仍受
店铺等级上限约束（§7.2）。

**空间形态升级线（家具级 → 房间级 → VIP 级）**：分区的升级不只是等级数字，而是**形态质变**——
普通化妆桌（开放角落）→ 独立化妆室（隔间 ×N，可并行）→ 艺人独立化妆间（专属套房 + 造型班底）：

| 分区 | 家具级（1~2★） | 房间级（3~4★ 解锁改造） | VIP 级（5★ 解锁改造） |
|---|---|---|---|
| 化妆 | 普通化妆桌（开放角落，1 桌 1 师傅） | **独立化妆室**（隔间 ×N，隐私 +，多人并行上妆） | **艺人独立化妆间**（专属套房 + 造型班底工位，接待团客单元） |
| 接待 | 前台桌 + 站位 | 接待厅（分区等候 + 选片角，座位跳档） | VIP 接待室（到店即入 + 专属客服，高星客不排队） |
| 棚拍 | 一面背景墙 | 独立影棚（可清场锁门，隐私 +） | 多主题影棚群（商拍级，开场地租赁副业线） |
| 选片 | 选片桌（共用，排队） | 独立选片室（不排队，谈单转化 +） | VIP 选片室（大单谈判 + 加印转化 +） |
| 修图 | 角落工位 | 修图室（交付提速） | 后期工作室（团队流水线 + AI 辅助位） |
| 休息 | 休息角（两把椅子 + 饮水机） | 员工休息室（精力恢复速度 ×2） | ——（员工福利到室级封顶，P2 再议 lounge） |

**形态改造规则**：

1. **主动大额投资**：新行动 `RenovateFacility`（TargetId=分区，Option=目标形态）——前置 =
   分区等级达阈值 + 店铺等级门槛（房间级 3★ / VIP 级 5★）；费用远高于同级升级，
   是中后期主要的"大奖时刻"（§1.4 硬规则 2）；
2. **有工期与代价**：改造 2~4 天，施工期该分区降效 50%（沿用 V1 扩张风险的显性表达）；
   改造完成时并发容量、隐私与满意度**跳档**（不是 +15%，是翻倍级质变）；
3. **形态是高星客群的接单门槛**：5★ 艺人团队单**必须**艺人独立化妆间，4★ 企业单需房间级
   接待 + 选片——进 `RequirementMissing` 统一检查（生成与接单两处共用，不漂移）；
4. **低形态不惩罚低客群**：街坊散客不介意开放化妆桌——是"高客群要高形态"，不是"人人都
   要堆资产"，避免逼新手超前投资；
5. 形态是 §4.7 服务分级的**物理前提**：3★ 全程陪同需要房间级化妆区，5★ 造型班底必须先有
   艺人独立化妆间。

### 6.7 微操收敛：日常引导，特殊时刻才微操

> 方针：**减少游戏进行中的微操，日常以引导为主**；把深度微操集中到"值得动手"的特殊时刻。

- **日常营业零强制微操**：订单走自动结算 + 轻引导（拍摄中选话术影响需求把握度，一次点击）；
  V1 的拍摄三轴微操（构图/时机/清晰度）调整为**可选**——跳过无惩罚，亲自玩有小加成；
- **深度微操只在特殊时刻开放**：
  - **锐评时刻（每周三投稿）**：选片 + 精修微操是核心玩法——挑哪张投稿、精修滑块调到哪，
    直接决定锐评档位，这是"值得动手"的仪式；
  - 外出采风（P2）：限时构图玩法；
  - 加急单临场决断（可选）：接不接、插不插队；
- 与 §4.7 呼应：低等级"带路快拍"本来就没微操；高等级"团队交付"玩家只出 brief——
  **微操密度随等级递减，判断与创意的权重递增**，这正是"自信心升级"的操作面表达。

### 6.8 破产防线：卖设备、救命大单与付费复活

现金流走到致死线之前，按**代价从低到高**排三道防线——玩家永远看得见自己还有几条命：

| 防线 | 内容 | 代价 | 获取 |
|---|---|---|---|
| 一道：变卖设备 | `SellEquipment`：7 项设备可**降级出售**，每降 1 级回收该级投入的 **40%**（折价变现；分区是不动产，不可卖，只能走被动收缩） | 产能与质量上限即时下降；依赖该设备的订单解锁条件**失效重估**（已接单不撤、新单不派） | 游戏内随时可卖 |
| 二道：救命大单 | 现金流进入危险/断裂（现金 < 7 天固定支出）时，收件箱出现"救命稻草"：**一笔 3~5 倍客单的紧急大单**（企业年会通宵跟拍 / 明星危机公关照），当天交付 | 通宵执行：全员精力 −40、老板精力见底、次日全店效率降；口碑小扣（"砸价救急"的传闻） | **看广告（免费）或付费复活解锁接单资格**；每 30 天至多 1 次 |
| 三道：被动收缩 | V1 既有：卖资产按废品价（回收 10~20%）、装修全损、缩面积 | 动线容量骤减、客人看到店在缩小 → 差评流失 | 现金 < 0 自动进入 |

三道防线全部失败（连续 7 天净流为负）→ 破产结算**不变**——防线是缓刑，不是赦免。

**商业化边界（与 §1.2 对齐）**：

- 广告 / 付费只解锁"接这张救命单的资格"，**不卖经营数值**——免费玩家看广告、付费玩家直接解锁，
  拿到的是**同一张单、同样的代价与收益**（对齐小游戏渠道已预留的广告位基建）；
- **凭证服务器权威**：广告回执 / 付费凭证由平台 SDK 回调登记（`Rescue.entitled`），
  `TakeRescueDeal` 前置校验 entitled + 冷却——客户端不能自行发钱（防作弊红线）；
- 冷却（每 30 天 1 次）与救命单参数进 `rescue` 目录，运营期可调；救命单自带高代价
  （精力崩 + 次日 debuff + 口碑小扣）保证"**救急不救穷**"——续命之后仍要靠经营自己爬出来；
- 命令驱动验收：无 UI 时由服务端测试参数直接授予 entitlement，跑通「触发 → 解锁 → 接单 →
  回血 → 代价生效」全链路。

## 七、店铺等级与成长全过程（一星小店 → 传奇影楼）

> 对标双点医院的「星级目标制」（见 [`原型调研-双点医院.md`](原型调研-双点医院.md) §2.9）：
> 星级是目标脉冲 + 存档点式的成就感；1 星推主线、2~3 星给精通玩家。
> 本作把这套东西改造成**单店无限经营**版本：等级只升不降、不上锁主线、不结束游戏。

### 7.1 设计总则

- **店铺等级（Grade）与口碑（Reputation）分离**：口碑是"当前状态"（会波动），等级是"历史成就"
  （只升不降）——口碑掉了不掉级，只发"复检提醒"文案（纯氛围无惩罚），杜绝长线挫败；
- 等级是**解锁门槛的组织者**：把散落的解锁条件（口碑 X 星、某设备、某资格）收编成一条可见
  天梯，玩家任何时刻都知道"我在哪、下一步去哪、还差什么"；
- 升级是**五维门槛**：技术（技能/资格/交付）+ 金钱（现金流/营收/估值）+ 场地（分区等级/形态/
  面积）+ 环境（设施完备度，P2 起换氛围分）+ 声望（口碑/粉丝/奖项）——**钱只是五分之一，
  缺一不可**。"从街边小店到明星商拍"的每一步都是五维齐备的结果，不是攒够钱就能买；
- 金钱维含收入类指标（累计营收 / 连续正现金流），把"赚钱"本身变成可验收的成长——这是
  "根据收入情况升级设备和房间"的规则化表达（见 §7.4）。

### 7.2 五级天梯（数值为初值提案，全部进 `grade` 目录域由服务端调）

| 等级 | 名称 | 主力客群（进化方向） | 达成条件（五维，全部满足） | 解锁 | 一次性奖励 |
|---|---|---|---|---|---|
| 1★ | 街角小店 | **街坊散客**：价格敏感、耐心低、差评多、砍价狠（吵架高发） | 初始 | 订单：证件照/标准写真/网红打卡（按 V1 附加条件）；设施上限 2 级；员工上限 2；无扩张 | — |
| 2★ | 口碑相馆 | **大众写真客**：看性价比、跟风打卡、传播力中 | 技术：任一员工技能 ≥ 3；金钱：连续净现金流为正 ≥ 14 天；场地：接待区 ≥ 2 且棚拍区 ≥ 2；声望：口碑 ≥ 3.0 且累计交付 ≥ 50 单 | 向右扩店 ①；婚纱订单（另需新娘妆资格）；设施上限 3；员工上限 4；广告渠道 4 个；休息区建造 | 粉丝 +200，技能点 +2 |
| 3★ | 社区名店 | **品质家庭客**：重服务与陪同、复购强、爱介绍客（留存主力） | 技术：专精资格员工 ≥ 1；金钱：累计营收 ≥ 100,000；场地：化妆区 ≥ 3；环境：四大分区（接待/化妆/棚拍/后期）均 ≥ 2；声望：口碑 ≥ 3.5 且粉丝 ≥ 1,000 | 亲子/宠物订单（另需道具）；企业形象照订单；商拍设备线；**空间形态改造·房间级**（化妆室/接待厅/独立选片室，§6.6）；向右 ②/向后扩张；设施上限 4；员工上限 6；全渠道广告；团建 | 粉丝 +800，技能点 +5 |
| 4★ | 城市名店 | **企业/专业客**：价格不敏感、要求高、验收严 | 技术：高端定制交付 ≥ 5 单；金钱：当期不可替代度 > AI 替代能力；场地：房间级形态改造 ≥ 2 处；环境：四大分区均 ≥ 3；声望：口碑 ≥ 4.0 且里程碑 ≥ 5 项 | 二楼；大师设备（设施 5 级）；广告商拍订单；指名复购客系统；员工上限 8 | 粉丝 +3,000，品牌推力 + |
| 5★ | 传奇影楼 | **艺人团队/广告主**：价格无所谓、要的是想法与执行、指名度高、自带流量 | 技术：大师资格员工 ≥ 2；金钱：门店估值 ≥ 500,000；场地：VIP 级形态 ≥ 1 处（如艺人独立化妆间）；环境：四大分区均 ≥ 4（P2 换氛围分）；声望：口碑 ≥ 4.8 且年度评奖 ≥ 3 项 | 全部订单与扩张；**空间形态改造·VIP 级**（艺人独立化妆间/多主题影棚群/VIP 接待室，§6.6）；**传奇里程碑**（无限计数：万单、十年店、百件作品集、全专精班底…）——无限经营的后期目标供给 | 传奇店牌（纯荣誉） |

- **环境维的代理指标**：P0/P1 用"设施完备度"（四大分区最低等级）代理环境水平，P2 氛围分
  上线后切换数据源（`grade` 目录条件热调，不改协议）；
- **升级评审展示五维缺口**：不满足时逐维显示"差多少"（技术：还差 1 位专精资格；场地：化妆区
  3→差 1 级…），玩家永远知道短板在哪一维——这本身就是引导；
- **门店估值** = 现金 + 累计设施投入 × 0.6（对标双点医院"医院价值 = 现金 + 已建资产估值"，
  把"赚了钱"翻译成"店值钱了"）；
- **客群进化曲线是爽感主线（自信心升级）**：从"为 20 块磨半小时、动辄差评"到"钱不是问题，
  你要给我想法"——客群的态度差就是玩家变强的镜子。每一级用文案、行为与无理取闹频率
  **显性表达**：低星级砍价挑刺嘴脸多，高星级变成专业对话与指名委托；
- 操作面的同构进化：微操密度随等级递减（亲自带路 → 团队交付，见 §6.7），判断与创意权重递增；
- V1 订单解锁条件里的"口碑 X 星"逐步改挂 `Grade`（资格/道具等附加条件保留），迁移见 §7.5；
- 成长曲线对位（V1 §8.3）：1★=生存、2★=稳定、3★=扩张、4★=竞争、5★+=无限。

### 7.3 升级评审（仪式感）

- 条件由回合钩子（order=60，动线结算后、现金流结算前）自动判定，**达成即"评审通过"**：
  全屏升级时刻（新店牌 + 解锁清单逐条点亮 + 奖励发放），收件箱留档可回看；
- 晨会常驻「距下一星」五维缺口：每一维展示最接近的条件及当前值（"技术：专精资格 0/1；
  金钱：连续正现金流 11/14 天；场地：化妆区 2/3；环境：后期区 1/2；声望：口碑 3.3/3.5"）
  ——把长线目标拆成每天看得见的刻度。

### 7.4 收入 → 设备与房间的再投入节奏（投资决策表）

按**现金流信号**分四阶段给出推荐投入（晨会推荐引擎的规则来源；每项升级在目录标注预计回本天数）：

| 经营阶段（现金流信号） | 优先投入 | 回报逻辑 |
|---|---|---|
| 生存期（月净流 < 1,000 或现金 < 30 天固定支出） | 只投小件：修图设备 2 级、接待区 2 级 | 交付提速 → 周转加快；接待区 = 时段 +1 = 纯增量；**忌扩店忌重资产** |
| 站稳期（连续 30 天净流为正，冲 2★/3★） | 化妆区 2~3 级 + 化妆师专精（婚纱线）；休息区；助理 1 名 | 婚纱是第一利润带；休息区防离岗损失；助理保环境维护闭环 |
| 扩张期（月净流 > 5,000，3★ 后） | 向右扩店（工位 × 产能）；灯光/镜头 3 级；修图师资格 | 复杂光影订单单价高；扩店摊薄固定支出占比 |
| 升档期（3★ 后冲高客群） | **空间形态改造**（独立化妆室/独立选片室 → 艺人独立化妆间） | 形态是高星客群的接单门槛；大额投资带工期，回收靠客单跳档与班底产能 |
| 竞争期（AI 冲击中后期，4★ 线） | 大师设备；二楼；品牌内容与 AI 订阅的权衡；VIP 打分冲刺 | 质量天花板 = 高端订单与不可替代度来源 |

- **回收期法则**：单项投入 ≤ 预计 30 天增量收入才推荐（晨会据此给"建议投/建议缓"）；
- **先瓶颈后天花板**：动线复盘热力图指出堵塞工位 → 优先该工位容量（分区等级/并发）；
  质量投诉为主 → 才投质量设备（机身/镜头）。对标双点医院"先诊断后治疗"的扩建次序；
- 扩张失败形态显性化（沿用 V1 扩张风险）：固定支出跳涨 + 施工降效 + 收入没跟上 = 亏损螺旋，
  晨会在扩张确认时展示"预计新增日固定支出 vs 预计新增日收入"对照。

### 7.5 双点医院经验对照与取舍

| 双点医院做法 | 本作取舍 |
|---|---|
| 星级达成瞬间 fanfare | **搬**：升级评审仪式（§7.3） |
| 1 星解锁下一院（关卡制） | **改造→已落地（2026-09-14）**：原型 `ClientPrototype` 采用快门县地图——5 地点各自独立建档与三星任务链，1 星解锁下一地点；店内升级保留「只升不降」天梯语义 |
| 医院等级越高客流越大、声望越难维持（攻略圈"压级"打法） | **不搬隐性惩罚**：本作用显性的扩张风险表达张力（固定支出/施工/被动收缩），不做"等级拖累口碑"的暗坑 |
| 医院价值 = 现金 + 资产 | **搬**：门店估值（5★ 条件与传奇里程碑计数） |
| 2~3 星精通目标 + Kudosh 收集 | **改造**：里程碑成就 + 年度评奖（§6.3）承担同一角色 |

### 7.6 与既有系统的接口

- 口碑（`Reputation`）与口碑星级门槛（`level` 目录）**保持现状含义**；店铺等级是新增维度，
  不改口碑的任何现有判定；
- 订单/设施/扩张的解锁判定逐步以 `Grade` 为前置（`RequirementMissing` 统一实现，两处共用不变）；
- 里程碑/年度评奖（§6.3）是 4★/5★ 的条件来源；动线复盘热力图（§8.5）是投资决策的依据来源。

## 八、操作流程与体验优化

### 8.1 V1 痛点清单

| # | 痛点 | 表现 |
|---|---|---|
| 1 | 决策分散 | 例行决策散在 8 个页签，一天要点十几处 |
| 2 | 模态拦截 | 客服事件锁死所有行动（`GuardServiceEvent` 前置条件拦一切） |
| 3 | 因果不可见 | 差评/退款凭空出现，看不到"为什么" |
| 4 | 无过程演出 | 一天是一张报表，没有"店里在营业"的画面 |
| 5 | 新手无引导 | 17 个行动一次性暴露 |

### 8.2 晨会（一日之计）—— 例行决策聚合

晨会面板一个屏幕装完当日全部例行项，每项给**推荐默认值**与理由，`一键应用` 后进入营业幕：

| 区块 | 内容 | 推荐规则（示例） |
|---|---|---|
| 今日预约预览 | 预约池 + walk-in 预估 + 时段占用条 | 溢出 → 建议提价档或缩 walk-in |
| 排期指派 | 订单 × 员工 × 时段（可切日历视图手动拖） | 按技能匹配 + 精力 + 关系组合自动排 |
| 员工预警 | 谁精力 < 40 / 谁想走（去留意愿 < 60，标注成长型/普通） | 建议排休；成长型想走 → 红色建议加薪挽留，普通 → 就近补招 |
| 现金流预测 | 30 天固定支出线 + 今日预计净流 | 危险态 → 建议停广告/裁变动支出 |
| 待办 | 收件箱未清事件、今日锐评提醒 | — |
| 店铺进度 | 距下一星最接近的 3 项条件与当前值（§7.3） | —— |

**体验指标：例行一天 ≤ 3 次点击**（打开晨会 → 一键应用 → 结束营业）。

### 8.3 事件收件箱替代全模态

| 级别 | 例子 | 行为 |
|---|---|---|
| 必须处理 | 破产警告、结局 | 全模态（仅此两级保留 V1 的硬拦截） |
| 立即处理 | 吵架进行中、加急请求 | 营业幕自动暂停 + 红点，可设忽略继续 |
| 可攒 | 客服投诉、线上差评 | 收件箱列表，营业结束前清空即可 |

服务端配套改动：`GuardServiceEvent` 前置条件从"锁一切行动"**收窄为锁 `NextDay` 与涉事订单的
`DeliverOrder`"；兜底不变：每条客服事件至少一个 0 成本选项（防锁死，V1 已保证）。

### 8.4 排期与指派

- 日历视图：8 时段 × 工位 的占用网格，拖拽指派；
- **自动排程助手**（晨会默认）：技能匹配 > 精力 > 黄金时段（夜猫子/早起鸟）；
- 记住上一次方案作为次日默认（一键复用）。

### 8.5 反馈与可读性

- **员工头顶气泡**：状态图标（累 / 想走；图标用文案表符号，遵守 UI 规范禁 Emoji）；
- **客人即现金流演出**：客单价标签、结账金额飞入顶栏、流失金额变红飘走 + 成因（§4.6）；
- **动线热力图**：结算幕给出当日 Top3 等待工位与损失估算（"选片段今日累计等待 9 时段，
  升级选片台预计 +2 单/天"）；
- **30 天现金流预测条**：固定支出线 + 已知预约收入（V1 已有现金流四态，加前瞻）；
- 日报升级为**日报 + 周报趋势**（口碑/粉丝/净现金流折线）；
- **周反思会（每周第 7 天结算幕后，不弹模态）**：本周净流 vs 上周、**流失金额 Top3 + 成因**
  （等太久/质量低/员工出错/谈崩）、留存率（复购比例）与传播数（分享 N 次/发布 N 次 → 带来
  客流）、一条"最值得改的事"（推荐引擎给行动建议）。定位：**晨会管今天做什么，周反思管
  这周哪里在漏钱**——两者都是引导，不是操作负担；
- 大单完成、锐评封神 → 全屏庆祝时刻（结算幕内，不打断操作）；**升级评审通过 → 全屏店牌换新 +
  解锁清单逐条点亮**（§7.3）。

### 8.6 新手引导（前 3 天剧本化）

第 4 天起进入自由经营；引导期天数可配置（服务端目录下发，客户端不硬编码）。

### 9.4 协议与 UiAction 增量

- 新 UiAction 字段仅 1 个：`SlotIndex`（int，排期起始时段）；**必须同步登记
  `KitchenCommandRunner.s_setters`**（现有硬性要求）；
- 其余参数复用：`AssignSchedule`（TargetId=预约号，Option=员工 id，SlotIndex=时段）、
  `SetWalkInPolicy`（Option=档位）、`RestStaff`/`ConsoleStaff`（TargetId=员工号）、
  `RenovateFacility`（TargetId=分区 id，Option=目标形态 id）——**无需新增字段**；
- `order` 目录条目新增 `stations` 字段（各环节路径与耗时系数）——目录下发，客户端不硬编码。

### 9.7 风险与未决

| 风险 | 对策 |
|---|---|
| 确定性 vs 演出自由度 | 演出只消费 `Flow`；一切判定在服务端（§3.4） |
| 移动端小人数量性能 | 同屏动线小人上限（如 12），超出用队列摘要表示 |
| 动线数值爆炸（环节×并发×需求） | P0 先固定移动系数，目录化全部参数，`schedule_hint` 给出推荐基线 |
| 前置条件收窄后的边界 | 保底频率 + 每事件 ≥1 零成本选项（V1 兜底沿用） |
| 页签合并的信息丢失 | 争执/锐评入口在收件箱与订单上下文里保留，上线前跑全面板进出关返回用例 |
